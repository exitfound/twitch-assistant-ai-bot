# Кинозал – сервер показа фильмов

Кинозал – свой сайт с плеером и чатом, куда эфир уходит на время фильма, пока Twitch показывает заглушку: фильмы в эфире Twitch приносят каналу DMCA-страйки. Соединение OBS → Twitch при этом не рвётся, и Twitch не видит «стрим оффлайн». Ссылку и код входа бот объявляет в чате Twitch.

Сервер кинозала живёт в каталоге `kinozal/` этого репозитория, а работает на отдельном хосте: это не служба бота и не часть его образа. С ботом его связывает только HTTP API шлюза. Сторона бота – команды `!film`, страховки сеанса и мост Twitch → кинозал – описана в BOT.md, «Шаг 7и: Команда `!film`» и «Мост чатов кинозала». Настройка OBS и порядок киновечера – [KINOZAL-OBS.md](KINOZAL-OBS.md).

Рамки: до ~20 зрителей, задержка 5–10 с (HLS), зрители в основном из РФ и СНГ.

## Схема

```
OBS (Windows)
 ├─ основной выход (Program) ──RTMP──> Twitch        ← не переподключается никогда
 │    любые рабочие сцены; режим кино: поверх всех сцен заглушка KINO
 └─ Branch Output на сцене КИНОПОДРУБ ──RTMP──> сервер кинозала: Owncast
      (свой энкодер NVENC, мастер-аудио дорожка 6: фильм + микрофон)

Бот ──HTTPS, Bearer──> API шлюза: открыть, переименовать, закрыть сеанс; отметка раз в минуту; строки чата Twitch

Сервер кинозала, домен из FILM_URL (Docker Compose)
 ├─ Caddy   – TLS, forward_auth → gate, /admin → 404
 ├─ gate    – вход через Twitch и код → подписанная cookie; API сеанса для бота; аренда 180 с; мост чатов; баны
 └─ Owncast – приём RTMP, HLS без перекодирования, встроенный чат, без VOD, своё оформление
```

Второй поток кодирует сам OBS, отдельно от эфира. Серверу ничего не нужно перекодировать (CPU почти не нужен), а Twitch переключения не замечает.

## Конфиг и секреты

Отдельного файла настроек у кинозала нет: оператор пишет свои значения в `.env` бота, а секреты сервера живут только на сервере.

- **`.env` бота** – секция «Кинозал: сервер» (`KINOZAL_HOST` – `user@host` или имя хоста из `~/.ssh/config`, `KINOZAL_KEY` – путь к ключу SSH, пусто – ssh-agent или конфиг, `KINOZAL_DIR` – каталог на хосте, по умолчанию `/opt/kinozal`, `KINOZAL_TWITCH_CLIENT_ID` / `_SECRET` – приложение Twitch кинозала) и общие с ботом `FILM_URL` (из него берётся домен), `FILM_API_TOKEN` (он же `GATE_API_TOKEN` шлюза) и `TWITCH_CHANNEL`. Их читает только `kinozal.sh`; любое значение можно задать и переменной окружения, она важнее файла (`KINOZAL_ENV` – другой путь к файлу). В скрипте нет ничего, что отличается у разных операторов. Чего не хватает, он называет и останавливается; хост, путь к ключу, домен, канал и каталог проверяет на допустимые символы, раз они попадают в команды на хосте.
- **`.env` сервера** (`<KINOZAL_DIR>/.env`, вне git, `rsync` его не трогает). При первом `deploy` хост генерирует свои секреты: `OWNCAST_ADMIN_PASSWORD`, `OWNCAST_STREAM_KEY`, `GATE_SECRET` (`openssl rand`) – они остаются только там, на рабочую машину не копируются. Каждый `deploy` переписывает туда значения оператора: `KINOZAL_DOMAIN`, `TWITCH_CHANNEL`, `GATE_API_TOKEN`, `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`. Из домена compose собирает `GATE_PUBLIC_URL` шлюза и адрес сайта в `Caddyfile` (`{$KINOZAL_DOMAIN}`); без домена или канала стек не поднимется. Когда секрет сервера нужен на рабочей машине, скрипт читает его по SSH в момент запуска: пароль Owncast – для `setup` и `style`, `GATE_SECRET` – для `link`, ключ потока – для `stream-key`.

Значения бота и кинозала поэтому совпадают сами:

| `.env` бота | `.env` сервера | Что |
|---|---|---|
| `FILM_API_TOKEN` | `GATE_API_TOKEN` | Bearer-токен API сеанса |
| `FILM_URL` | `KINOZAL_DOMAIN` (`GATE_PUBLIC_URL` шлюза – `https://` + домен) | адрес сайта |
| `TWITCH_CHANNEL` | `TWITCH_CHANNEL` | канал, чьих фолловеров и сабов пускает шлюз |
| `FILM_HALL_MARK` | `HALL_MARK` (по умолчанию `🎬 [KZ]`) | метка строки из кинозала в Twitch; не передаётся, обе стороны оставляют значение по умолчанию |

Twitch-приложение у кинозала своё (Redirect URL `<FILM_URL>/_gate/twitch/callback`), с ботом его ключи не общие.

## Шлюз: вход и доступ

Caddy спрашивает `/_gate/auth` перед каждым запросом к Owncast: 200 пропускает, 302 отправляет на страницу входа `/_gate/enter`.

- **Вход – Twitch и код.** Сначала кнопка Twitch: шлюз проверяет токеном зрителя фолов или подписку на `TWITCH_CHANNEL` (стример проходит всегда). Если зритель не дал права писать в чат, токен сразу отзывается; если дал – шлюз держит токен в памяти до конца сеанса для моста (ниже). Зритель запоминается cookie `kzp` (30 минут, привязана к сеансу), страница показывает «Twitch: ник ✓» и поле кода. Верный код ставит cookie `kz` = `сеанс.подпись` и, после входа через Twitch, `.id_Twitch.подпись`: по id забаненный вылетает с видео сразу. Cookie без id тоже принимается. Без `TWITCH_CLIENT_ID` и `TWITCH_CLIENT_SECRET` вход – по одному коду.
- **Код живёт один сеанс.** Новый сеанс (`POST /_gate/api/session`) или его закрытие (`DELETE`) делает недействительными все выданные cookie; смена названия (`PATCH {"title"}`) их не трогает. Название видно на странице входа. Подбор кода ограничен: не больше 10 неверных кодов за 10 минут на аккаунт Twitch и 50 на IP (за одним NAT мобильного оператора сидят многие зрители, и опечатки одного не закрывают вход остальным); без приложения Twitch – 10 на IP. Адрес возврата `next` – только путь этого сайта: `//…`, `/\…` и управляющие символы или пробелы в нём заменяются на `/` (браузер выбрасывает табуляцию, и `/<tab>/evil.com` стал бы чужим адресом).
- **Аренда.** Любой запрос к API продлевает сеанс; без запросов дольше `GATE_LEASE_SECONDS` (180, `0` – без аренды) сеанс закрывается сам. Бот отмечается раз в минуту, поэтому кинозал закрывается, когда упал бот или выключилась его машина. Сеанс, открытый вручную через `curl`, тоже закроется через 3 минуты без повторных `GET`.
- **Анонимов нет.** У каждого вошедшего через Twitch – свой пользователь чата Owncast с ником из Twitch (`chatters.json`): в пределах сеанса тот же, в новом сеансе – новый; отключённый в чате остаётся отключённым. Сменить ник нельзя: пунктов меню нет (`custom.css`), а сменившему через консоль шлюз возвращает ник из Twitch токеном зрителя (событие `NAME_CHANGE`, не чаще раза в 30 с).
- **Модератор чата – только стример:** при его входе через Twitch шлюз делает его пользователя модератором Owncast.
- **Постоянный пропуск стримера** – `/_gate/host?key=…`: cookie `kzh` на год, без кода и сеанса, для дока с чатом в OBS. Ключ выводится из `GATE_SECRET` (смена секрета отзывает его), подбор ограничен как подбор кода; ссылку печатает `make -C kinozal link`. Док пишет от пользователя стримера, если стример хоть раз входил через Twitch.
- **«Выйти»** (`/_gate/logout`): cookie стёрты, токен Twitch зрителя отозван, токен чата удалён из localStorage; следующий визит начинается со страницы входа.

Все обработчики шлюза асинхронные: сеанс, токены зрителей и файлы состояния меняются только в цикле событий. Синхронный обработчик FastAPI выполнялся бы в отдельном потоке и гонялся бы с циклом (общий `*.tmp`, `session = None` посреди проверки).

Страница входа и её ошибки – на языке из cookie `kz_lang` (раздел «Язык»). Превью ссылки (Discord, Telegram) тоже берётся со страницы входа: у робота превью нет cookie, и Caddy отправляет его туда. Поэтому на ней og-теги с двуязычной карточкой – «Кинозал · Cinema» и `PREVIEW_SUMMARY`, тот же текст, что `kinozal.sh setup` ставит в описание сервера Owncast.

Открытые эндпоинты без входа: `GET /_gate/now` – открыт ли сеанс, название и начало (для заглушки в OBS, с CORS) и страница `/_gate/enter`. Вошедшим: `GET /_gate/live` – начало сеанса, время шлюза и `voice` (уходят ли строки зрителя в Twitch), для таймера под плеером.

## Мост чатов: сторона шлюза

- **Twitch → кинозал.** Бот шлёт каждую строку Twitch в `POST /_gate/api/chat` (тело – BOT.md, «Мост чатов кинозала»). Шлюз экранирует разметку и пишет строку от двойника автора – пользователя-интеграции «ник [TW]» со своим цветом (`twins.json`); не вышло – от пользователя «Twitch» с ником в тексте. Исключение – отказ 401, причину которого шлюз не смог проверить (история чата не прочиталась): автор мог быть только что забанен, поэтому строка не пишется вовсе, бот получает 502. Хвост `[TW]` (`TWIN_MARK`) обязателен: Owncast резервирует имена интеграций. Строки забаненных в кинозале не пишутся (`{"sent": false, "banned": true}`): бан сверяется и с ником строки, и с полем `login`, потому что бан зрителя кинозала хранится по логину Twitch, а ник в строке – отображаемое имя. Цвет, значки и смайлы строки шлюз копит для страницы (`/_gate/look`, ниже).
- **Кинозал → Twitch.** Шлюз сам читает чат Owncast (`hall_loop`, раз в `HALL_POLL_SECONDS` = 2 с) и строку зрителя, вошедшего через Twitch, отправляет в Twitch от его аккаунта, его токеном (право `user:write:chat`), с меткой `HALL_MARK`. Зрители сопоставляются по id пользователя Owncast, переименование в чате на это не влияет. Невидимая метка ответа (ниже) в Twitch не уходит: `plain()` вырезает её вместе с обрывками. Тот же цикл сверяет баны и закрывает сеанс по истёкшей аренде, поэтому любой сбой в нём (Owncast оборвал ответ на перезапуске, битая запись) пишется в лог, а цикл идёт дальше.
- **Токены зрителей – только в памяти и только на сеанс.** Конец сеанса (DELETE, новый сеанс, истёкшая аренда) отзывает их все. Перезапуск шлюза их теряет: строки из кинозала перестают уходить в Twitch, `/_gate/live` отвечает `voice: false`, и страница показывает над полем ввода плашку «Твои сообщения сейчас не уходят в чат Twitch» с кнопкой «Переподключить» (`custom.js` «reconnect»): вход через Twitch заново, код уже введён – сразу обратно в чат.
- Токен интеграции Owncast шлюз получает через admin API, наружу он не выходит.
- **Флуд в кинозале разрешён** (`chat/spamprotectionenabled=false`). Ограничения Twitch для строк из кинозала остаются (та же строка чаще раза в 30 с, ~20 строк за 30 с): такие видны в кинозале, но не в Twitch.

## Чат кинозала

- **Вид:** «время [TW] значки ник: текст» в одну строку, 16px. Время серое, 24 ч, по часам зрителя (из `title` строки Owncast). `[TW]` – строка из Twitch, цвет `#A970FF` (контраст ~5:1). Значок «бот» у двойников и значки Owncast при значках Twitch скрыты. Поле ввода в одну строку растёт до 4; Enter отправляет.
- **Цвета ников, смайлы, значки** – `GET /_gate/look` (только вошедшим; `custom.js` опрашивает раз в 30 с), хранятся в `look.json`:
  - `colors` – ник (casefold) → цвет Twitch: для строк из Twitch – от бота, для зрителя кинозала – при входе (`helix/chat/color`). Тёмные осветляются до 4,5:1 к панели. Не выбравший цвет в Twitch получает цвет Owncast (8 слотов).
  - `emotes` – название → id: глобальные и канала (Helix, токен приложения, кэш 6 ч) плюс виденные в строках Twitch, в том числе сабовые чужих каналов. Страница заменяет слова на картинки `static-cdn.jtvnw.net`: внешние картинки из сообщений Owncast вырезает. В кнопке эмодзи Owncast смайлов Twitch нет, их пишут названием; BTTV, 7TV, FFZ нет.
  - `badges` (ник → `["moderator/1", …]`, от бота; стример при входе – broadcaster) и `badgeImages` (только используемые; глобальные и канала из Helix, значок канала главнее). У зрителя кинозала, не писавшего в Twitch, значков нет.
- **Автопрокрутка** (`custom.js` «chat autoscroll») – своя: лента держится у последнего сообщения, пока зритель сам не прокрутил вверх. Отпускает её любое настоящее движение вверх – колесом, PageUp, ↑, Home, полосой, пальцем; колесо, которое ничего не сдвинуло, и Ctrl+колесо (масштаб) не в счёт. Положение берётся из событий прокрутки, а не колеса: Chromium сдвигает ленту раньше, чем приходит событие колеса. Вернулся вниз ближе 60px или нажал «К новым сообщениям» – лента снова следит. Порог 60px действует только на возврат: шаг колеса 12–57px меньше порога, а virtuoso перерисовывает ленту на каждом шаге, и с порогом на отпускание лента застревала бы внизу. Перетаскивание полосы считается прокруткой зрителя, пока кнопка мыши зажата (потерянное отпускание ловится по движению без кнопок и по контекстному меню), и место чтения идёт за полосой: иначе правки Owncast возвращают ленту к началу перетаскивания, и она мигает между двумя положениями. Если ленту тянет вниз не зритель (Owncast «догоняет низ» на новом сообщении или недосчитав высоту строк), `custom.js` возвращает её на место. Остаются мелкие поправки Owncast (~16px) при перетаскивании: строки разной высоты из-за шрифта 16px.
- **Участники** (`custom.js` «chat members»): шапка «Чат» с кнопкой, как в Twitch, открывает поверх ленты список тех, кто сейчас в чате кинозала. `GET /_gate/users` (только вошедшим) – подключённые к чату Owncast (`/api/admin/chat/clients`), по одному на пользователя, без ботов, `mod` – модератор Owncast. Ответ и сбой кэшируются на 5 с, запрос к Owncast один на всех (`users_lock`): зависший Owncast не занимает потоки, на которых работает мост; Owncast не ответил – 502. Открытый список обновляется раз в 10 с. Поиск, группы Стример / Модераторы / VIP / Зрители по значкам Twitch, ники цветом из Twitch, клик по нику – «@ник» в поле ввода. У ленты свой слой (`isolation: isolate`): у текста строк Owncast `z-index: 100`.
- **«@» в поле ввода** (`custom.js` «mentions»): подсказка до 7 ников – авторы недавних строк (свежие первыми, включая строки из Twitch) и кто в чате кинозала; сначала начинающиеся с набранного, потом содержащие; без себя и без «Twitch». ↑/↓ – выбор, Tab или Enter – вставить, Esc – закрыть; клавиши перехватываются в фазе захвата на document, раньше Owncast. Вставка через `document.execCommand("insertText")`: для Owncast это обычный ввод, Ctrl+Z работает.
- **Ответ на строку** (`custom.js` «replies»): стрелка на строке при наведении (на пальце – по касанию) → над полем плашка «↩ Ответ @ник: текст» с крестиком, в поле – «@ник». У всех над ответом – плашка с цитатой. Ответ несёт id исходной строки невидимой меткой после ника: U+2063 и по три символа нулевой ширины (U+200B, U+200C, U+200D, U+2060) на знак id – Owncast её не чистит, подсветку упоминания она не ломает. Цитата берётся из истории чата (`GET /api/chat` с токеном из localStorage): `/api/chat` отдаёт ~50 последних строк, поэтому страница копит историю сама (до 3000 строк, подтягивая не чаще раза в 10 с), и отвечать можно на строки старше этих 50. Строка ленты связывается с записью истории по автору, тексту и минуте, а среди одинаковых – по месту снизу. Новому зрителю токен Owncast выдаёт через ~1 с после загрузки, история его ждёт. U+200D вне метки не вырезается: он склеивает составные эмодзи.
- **Подписи Owncast в русском режиме:** `custom.js` переводит подписи Owncast и video.js на лету (словарь `RU`, шаблоны `RX`, фразы с разметкой `PHRASES`) и исправляет встроенный перевод Owncast `ru`; строки сообщений не трогает. В английском режиме перевод выключен, Owncast показывает свой английский (раздел «Язык»).
- Кнопки и строки на пальце – от 44px.

## Модерация и баны

Модерирует только стример.

- **Кнопки у строки** (`custom.js` «moderation»), левее стрелки ответа: «Удалить» (сразу, без подтверждения) и «Забанить» (первое нажатие – красная «Забанить?», второе за 3 с – бан). Итог – плашка вверху чата на 6 с: «ник забанен…» с кнопкой «Баны» или причина отказа. Работают и на строках из Twitch. Запросы идут в API модерации Owncast токеном стримера (`/api/chat/messagevisibility`, `/api/chat/users/setenabled`), id сообщения и автора – из истории чата, автор сверяется с ником строки без «[TW]». Бана нет у своих строк, у строк со значком стримера и у строк «Twitch»: это запасной отправитель моста, его бан отрезал бы весь мост. Меню Owncast «…» скрыто CSS, но остаётся в разметке: по нему `custom.js` узнаёт модератора.
- **Бан насовсем.** `sync_bans()` раз в 10 с, пока сеанс открыт, сверяет отключённых в Owncast и запоминает их по аккаунту Twitch в `bans.json` (`id:<id Twitch>` – зритель кинозала, `tw:<ник>` – зритель Twitch). Забаненный вылетает с видео, не войдёт через Twitch, его строки из Twitch в кинозал не идут. Двойника Owncast показывает только в истории чата: бан зрителя Twitch снимается сверкой, лишь пока двойник там виден и включён (разбан в админке Owncast); ушедший из истории двойник остаётся забаненным до разбана в окне «Баны».
- **Окно «Баны»** – кнопка в шапке чата, только стримеру (вход через Twitch под каналом или постоянный пропуск; остальным `GET /_gate/bans` отвечает 403). Список после сверки с Owncast: ник, «зритель кинозала» или «зритель Twitch», дата; открытое окно обновляется раз в 10 с, число на кнопке – раз в минуту и после каждого бана. «Разбанить» → `POST /_gate/unban {"key"}`: шлюз включает пользователей чата и снимает бан по IP (Owncast при бане подключённого зрителя банит IP его подключений, и включение пользователя этот бан не снимает), бан забывается. Сверка и разбан идут под одним замком (`bans_lock`), сверка не вернёт снятый бан.
- **Запасной путь** – админка Owncast через туннель (раздел «Эксплуатация»), Chat → Users и IP Bans; шлюз увидит изменение за 10 с.
- Строку из кинозала, уже ушедшую в Twitch (~2 с), удаление в кинозале из Twitch не убирает; бан в кинозале не банит в Twitch: у шлюза нет прав модератора Twitch.

## Язык: русский и английский

Сайт и страница входа говорят по-русски или по-английски.

- **Язык по умолчанию – язык браузера.** Пока зритель сам не выбрал язык, решает первый язык браузера: русский и языки СНГ, чьи носители обычно читают по-русски (`uk`, `be`, `kk`, `ky`, `uz`, `tg`, `tk`, `az`, `hy`), дают русский, остальные – английский. Шлюз читает его из `Accept-Language` (с учётом `q`), страница – из `navigator.languages`; список один и тот же (`RU_READERS` в `gate/app.py` и в `custom.js`). Без заголовка (боты, `curl`) – русский.

- **Явный выбор** хранится в cookie `kz_lang` (`ru` или `en`, на год, без HttpOnly: её читают и шлюз, и `custom.js`) и важнее языка браузера. Переключает его переключатель `RU | EN` в шапке сайта рядом с «Выйти»: текущий язык подсвечен, второй нажимается, каждый подписан на своём языке («Русский», «English»), а шрифт – как у «Выйти». Такой же переключатель стоит в углу страницы входа (`/_gate/lang?to=en&next=…` ставит cookie и возвращает на страницу входа).
- **Owncast** берёт свой язык только из параметра адреса `?lang=`, иначе – из языка браузера; запомнить язык он не умеет. Поэтому английский режим – это `?lang=en` в адресе. Шлюз добавляет его сам, когда после входа отправляет зрителя на сайт (`with_lang()`), и убирает в русском режиме. Если зритель открыл сайт без параметра, а браузер не английский (например, немецкий – Owncast показал бы свой немецкий перевод), `custom.js` один раз переходит на тот же адрес с `?lang=en`; кнопка языка ставит cookie и перезагружает страницу с параметром или без него.
- **Русский режим** – прежний: `custom.js` переводит английские подписи Owncast и правит его собственный перевод, значки Twitch подписаны по-русски (`BADGE_RU`), подсказка над ником – «ник, в чате с 23:51».
- **Английский режим:** перевода нет, значки подписаны так, как их называет Twitch. Название зала в шапке и во вкладке и текст «нет трансляции» Owncast хранит одной строкой на русском (`kinozal.sh setup` и `style`) – `custom.js` подменяет их английскими (`englishPage()`), а заголовок экрана «нет трансляции» – CSS по `html[lang="en"]`.
- **Тексты.** Все собственные надписи страницы – в объекте `TEXT` в начале `custom.js` (`ru` и `en`, ключи общие, `txt(key, {nick})` подставляет значения); все надписи страницы входа и ошибки входа – в `TEXT` в `gate/app.py` (`tr(lang, key)`). Новая надпись добавляется сразу на оба языка. Сообщения чата, ники и название фильма не переводятся. Подписи значков antd, которые читает экранный диктор (`send`, `smile`, `usergroup-add`…), в русском режиме тоже переведены.

Панель управления прозрачная поверх картинки, кнопки на одной оси, курсор прячется вместе с панелью. На плеере до 480px нет полосы прогресса, кнопки 40px – всё влезает от 320px.

Прокрутки страницы нет нигде (`overflow: hidden`).

## Owncast и Caddy

- **Owncast** настраивает `kinozal.sh setup`: имя «Кинозал», двуязычное описание, без индексации, тегов, соцссылок и уведомлений, защита от флуда выключена, логотип, автоплей, одно качество «Исходник» без перекодирования (passthrough видео и звука, ~5–6 Мбит/с) и только наш ключ потока (`abc123` по умолчанию удалён). VOD и каталог Owncast выключены. Выбора качества нет: перекодирование на небольшом инстансе съедает CPU-кредиты.
- **Caddy**: TLS от Let's Encrypt, `X-Robots-Tag: noindex`, `Referrer-Policy: no-referrer`, без заголовка `Server`. `/admin*` и `/api/admin*` снаружи – 404 (через `handle`: голый `respond` выполнился бы после блоков `handle` и не сработал бы). `/_gate/*` – прямо в шлюз. Всё остальное (сайт, HLS, websocket чата) – через `forward_auth` на `/_gate/auth`, без заголовков websocket (иначе uvicorn пишет «Unsupported upgrade request»). Caddyfile смонтирован каталогом, а не файлом: rsync заменяет inode, и bind-монтирование файла держало бы старый.

**Особенности Owncast 0.3.0**, на которые опирается шлюз:
- отключение пользователя в чате банит IP его подключений (IP из `X-Forwarded-For`, Caddy подделать его не даёт);
- имена интеграций зарезервированы: регистрация с таким ником получает хвост;
- забаненные интеграции не видны ни в списке отключённых, ни в списке токенов – только `user.disabledAt` в `GET /api/admin/chat/messages`. На 401 у двойника шлюз сначала проверяет бан: новый токен означал бы нового пользователя и обход бана;
- история интеграций – последние 50 сообщений, чтение требует `HAS_ADMIN_ACCESS`; `GET /api/admin/chat/messages` – вся история, новые сверху;
- внешние `<img src>` из сообщений вырезаются (остаётся `alt`), поэтому картинки рисует страница;
- после конца эфира чат зрителям закрыт, а строки зрителей вне эфира отбрасываются;
- автоплей – `autoplay` (`off`, `always`, `sound-only`), громкость – localStorage `owncast_volume`; свой JS – `customjavascript`, он грузится после React, и свои элементы `custom.js` вставляет заново по наблюдателю;
- встроенные переводы выбираются по языку браузера или `?lang=`.

## Эксплуатация

Каждая выкатка – по явному решению стримера.

- **Оформление** (`owncast/`, текст «нет трансляции») – без перезапусков, можно во время сеанса и при живом потоке: `make -C kinozal style` (`kinozal.sh style`) выгружает файлы из рабочего дерева прямо в Owncast через SSH-туннель, деплой для этого не нужен. Зрителям – обновить страницу.
- **Шлюз** – `make -C kinozal deploy` (`kinozal.sh deploy`: rsync + `docker compose up -d --build`, пересоздаётся только изменённый сервис) – **только при закрытом сеансе**: перезапуск шлюза теряет токены зрителей. `deploy` за этим следит: если новый образ шлюза отличается от запущенного или изменилась его конфигурация (хеш конфигурации compose против метки контейнера: туда входит и `.env`, который `deploy` пишет заново на каждом запуске), а сеанс открыт (`/_gate/now`; молчащий шлюз считается открытым), он поднимает только Owncast и Caddy, оставляет старый шлюз и выходит с кодом 3. Повторить – после `!film stop` или с `KINOZAL_FORCE_GATE=1`. JS, которому нужен новый эндпоинт шлюза, можно выкатить раньше: без эндпоинта он молча ничего не делает.
- **Бот** – перезапуск бота закрывает сеанс (BOT.md, «Шаг 7и»). Если выкатываются и бот, и шлюз: сначала бот (он закроет сеанс и скажет об этом в чат), затем проверить `{"active":false}` и выкатить шлюз.
- **`make -C kinozal setup` – только когда Owncast не получает поток:** он перезаписывает и настройки видео. Закрытый сеанс не значит, что потока нет: Branch Output шлёт, пока включён его глаз. Скрипт сам спрашивает `/api/status` и при живом потоке или без ответа отказывается, ничего не меняя; `KINOZAL_FORCE_STREAM=1` – всё равно выполнить. Две защиты сняты двумя разными флагами, чтобы, снимая одну, не снять заодно другую. Неудавшиеся настройки не обрывают прогон: скрипт пробует все и в конце называет неприменённые. Отдельная настройка Owncast – одним `POST /api/admin/config/…` на хосте. `docker compose restart` прерывает поток в кинозал на ~10 с (OBS переподключается сам).

С рабочей машины (`make -C kinozal <команда>` вызывает то же самое):

```bash
kinozal/kinozal.sh deploy          # выкатка
kinozal/kinozal.sh setup           # все настройки Owncast, только без потока
kinozal/kinozal.sh style           # только оформление
kinozal/kinozal.sh status          # стек, сеанс и поток на хосте
kinozal/kinozal.sh link            # ссылка для дока с чатом в OBS
kinozal/kinozal.sh stream-key      # ключ потока для OBS
```

На хосте нужны `docker compose`, `openssl` и `sudo` без пароля, на рабочей машине – `ssh`, `rsync`, `curl`, `python3`; скрипт проверяет их перед работой. `setup` и `style` ходят в админку Owncast через SSH-туннель на локальный сокет во временном каталоге: порт выбирать не нужно, другим пользователям машины он недоступен.

Команды на хосте – через `ssh -i "$KINOZAL_KEY" "$KINOZAL_HOST"`, из `KINOZAL_DIR`:

```bash
sudo docker compose ps
sudo docker exec kinozal-owncast-1 wget -qO- http://127.0.0.1:8080/api/status   # "online":true – поток идёт
```

**Состояние и сеанс вручную** (запрос продлевает аренду, как отметка бота):

```bash
# .env бота не годится для «. ./.env»: в нём есть значения с пробелами, поэтому две строки читаются отдельно
A="Authorization: Bearer $(sed -n 's/^FILM_API_TOKEN=//p' .env)"
U="$(sed -n 's/^FILM_URL=//p' .env)/_gate/api/session"
curl -s -H "$A" "$U"                 # состояние
curl -s -X POST   -H "$A" "$U"       # новый сеанс → {"code":"1234",…}
curl -s -X PATCH  -H "$A" -H 'Content-Type: application/json' -d '{"title":"Чужие"}' "$U"
curl -s -X DELETE -H "$A" "$U"
```

Без токена состояние видно на странице `<FILM_URL>/_gate/enter` или в `make -C kinozal status`.

**Админка Owncast** – только через туннель: `ssh -i "$KINOZAL_KEY" -L 8080:127.0.0.1:8080 "$KINOZAL_HOST"`, затем http://127.0.0.1:8080/admin (логин `admin`, пароль `OWNCAST_ADMIN_PASSWORD`).

**Тест-запись потока** – что реально получают зрители:

```bash
ssh -i "$KINOZAL_KEY" "$KINOZAL_HOST" 'sudo docker exec kinozal-owncast-1 sh -c "ffmpeg -loglevel error -i http://127.0.0.1:8080/hls/0/stream.m3u8 -t 30 -c copy -bsf:a aac_adtstoasc /tmp/t.mp4 && ffmpeg -nostats -i /tmp/t.mp4 -vn -af volumedetect -f null - 2>&1 | grep _volume"'
```

`max_volume: -91.0 dB` – полная тишина: на дорожку 6 ничего не попадает (KINOZAL-OBS.md, «Звук»). Тишина нормальна, если фильм не играет, режим кино выключен и стример молчит (на микрофоне шумовой гейт).

**Док с чатом в OBS:** ссылку печатает `make -C kinozal link` (ключ – из `GATE_SECRET`, прочитанного с хоста по SSH, домен – из `FILM_URL`). Ссылка – постоянный пропуск, её никому не показывать; отзыв – смена `GATE_SECRET` на хосте и пересоздание `gate`.

**На сайт с чатом по постоянному пропуску не заходить** не из OBS: Owncast выдаёт такому входу случайный ник, и зрители видят в чате ник не из Twitch. Прод проверяется по `/api/config` на хосте или в браузере с заблокированным `**/api/chat/register`.

## Проверка локально

- **Перед слиянием** правки кинозала – `make -C kinozal check` (ruff шлюза, shellcheck `kinozal.sh`, тесты) и `make -C kinozal audit`: корневой `make check` `kinozal/` не проверяет.
- **Тесты шлюза:** `make -C kinozal test` – в контейнере `python:3.14-slim` с зависимостями из `requirements-dev.txt`. Без Owncast тесты моста и чата пропускаются. С Owncast: `OWNCAST_URL=http://127.0.0.1:18080 OWNCAST_ADMIN_PASSWORD=testpass make -C kinozal test`; без живого потока пропускаются тесты, где пишет зритель. Тесты оставляют в Owncast своих пользователей и токены, от них они не зависят.
- **Owncast с потоком:**
  ```bash
  docker run -d --name oc-test -p 127.0.0.1:18080:8080 -p 127.0.0.1:19350:1935 owncast/owncast:0.3.0 -adminpassword testpass -streamkey testkey
  docker run -d --rm --name oc-stream --network host linuxserver/ffmpeg -re -f lavfi -i testsrc=size=320x180:rate=15 -f lavfi -i sine \
    -c:v libx264 -preset ultrafast -g 30 -c:a aac -f flv rtmp://127.0.0.1:19350/live/testkey
  OWNCAST_API=http://127.0.0.1:18080 OWNCAST_ADMIN_PASSWORD=testpass kinozal/kinozal.sh style --local   # оформление; setup --local – все настройки
  ```

## Известные ловушки

- **Элемент ленты чата не прячется через `display: none`.** Лента – виртуальный список (react-virtuoso): элемент высотой 0px он измерить не может и перестаёт рисовать ленту целиком – чат пуст, хотя писать в него можно. Так ломалась лента модератора, у которого Owncast вставляет строку «You are now a moderator» при каждом подключении; она спрятана высотой 1px.
- **Селекторы Owncast – только по вхождению** (`[class*="…"]:not(…)`), не `[class$=…]`: antd дописывает классы (`ant-tooltip-open`), и правило отваливается – мигает ник при наведении.
- **Вставки в строки чата меняют высоту после замера virtuoso**, и лента начинает «догонять низ». Любое новое оформление строки и правку автопрокрутки проверять сценариями «прокрутил вверх → пришли сообщения → остался на месте», «медленно вверх по 12px, пока чат пишет» и «тянуть полосу вверх и держать, пока чат пишет» в Chromium и Firefox. Полоса прокрутки видна только в настоящем Firefox (`Xvfb :99` и `headless: false`), в Chromium – без `--hide-scrollbars`.
- Своим кнопкам поверх плеера нужен `z-index` > 100; у панели управления Owncast `background-color … !important`.
- Подсказки antd добавляются в `body`: у страницы не должно быть своей прокрутки, иначе в Firefox на Windows полоса 17px дёргает раскладку.
- Кнопки video.js гасят всплытие клавиш – свои обработчики вешаются в фазе захвата.
- React перерисовывает страницу – свои элементы вставляются заново по наблюдателю.

## Хостинг

Сервер – инстанс AWS EC2 во Франкфурте с Ubuntu 24.04 и Docker Compose; Docker работает через `sudo`. Открыты только 22, 80, 443 (tcp и udp для HTTP/3) и 1935. RTMP защищён ключом потока Owncast, SSH – ключом.

- **IP не Elastic:** reboot его сохраняет, stop/start или пересоздание меняет, и A-запись `kinozal` ломается. DNS `kube.how` – в Cloudflare, запись `kinozal` – DNS only, без проксирования видео.
- **Трафик:** один сеанс (20 зрителей × ~5,5 Мбит/с × 3 ч) ≈ 150 ГБ исходящего; у AWS бесплатно 100 ГБ в месяц, дальше ~$0.09/ГБ. Снижается битрейтом Branch Output (3,5 Мбит/с для фильма почти не хуже) или переносом на VPS с включённым трафиком: публичный IPv4, трафик от 1 ТБ в месяц, порт от 200 Мбит/с, открытые 80, 443 и 1935.
- Домашний upload от 20 Мбит/с хватает на оба потока в 1080p. Домашняя машина в роли сервера не годится: раздача ~120 Мбит/с, светится домашний IP, а Cloudflare Tunnel запрещает видео.
- **Риск:** жалобы правообладателей могут прийти хостеру. Его снижают вход по коду только для фолловеров, отсутствие записей (VOD) и запрет индексации.
