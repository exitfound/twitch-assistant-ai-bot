# Twitch AI Bot

Twitch-бот для работы в чате канала на Twitch. Генерирует ответы через **Gemini 2.5 Flash**. Хранит полную историю чата в SQLite с полнотекстовым поиском (FTS5) и долговременной памятью между стримами (опционально).

- Python 3.11+
- [twitchio](https://github.com/TwitchIO/TwitchIO) 3.x – подключение к Twitch через EventSub (WebSocket), не IRC
- [google-genai](https://pypi.org/project/google-genai/) – Gemini API (модель `gemini-2.5-flash`)
- [aiosqlite](https://github.com/omnilib/aiosqlite) – асинхронная работа с SQLite в WAL-режиме
- [python-dotenv](https://pypi.org/project/python-dotenv/) – загрузка переменных окружения из `.env`

## Установка

### 1. Создать бот-аккаунт на Twitch

Зарегистрируй отдельный Twitch-аккаунт, который будет выступать ботом (например `securityexpert`). Это обычный аккаунт – специальной регистрации «как бот» не требуется. После создания аккаунта зайди в чат стримерского канала (под стримерским аккаунтом) и дай боту права модератора:

```
/mod botname
```

Модератор нужен чтобы бот мог писать в чат без ограничений Twitch по rate-limit. Делается один раз – разрешение хранится на стороне Twitch и сохраняется при переносе бота.

### 2. Создать приложение на dev.twitch.tv

1. Зайди на [dev.twitch.tv/console/apps](https://dev.twitch.tv/console/apps) под **бот-аккаунтом**
2. **Register Your Application**:
   - **Name** – любое название
   - **OAuth Redirect URLs** – `http://localhost:4343/oauth` (twitchio поднимает локальный сервер на этом порту для OAuth-flow)
   - **Category** – Chat Bot
3. После создания зайди в **Manage** → скопируй **Client ID**
4. Нажми **New Secret** → скопируй **Client Secret** (показывается один раз)

### 3. Узнать числовой ID бот-аккаунта

Twitch API работает с числовыми user ID, а не с никами. Узнать ID бот-аккаунта можно здесь: [streamweasels.com/tools/convert-twitch-username-to-user-id](https://www.streamweasels.com/tools/convert-twitch-username-to-user-id/) – введи ник бота, скопируй числовой ID.

### 4. Получить Gemini API Key

Зайди на [aistudio.google.com](https://aistudio.google.com/) → **Get API key** → создай ключ. Бесплатного тарифа достаточно для минимальной работы бота в чате.

### 5. Установить зависимости

```bash
git clone https://github.com/exitfound/twitch-assistant-ai-bot
cd twitch-assistant-ai-bot
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
```

### 6. Настроить .env

```bash
cp .env.example .env
```

Заполни обязательные переменные (подробности в секции [Переменные окружения](#переменные-окружения)):

```env
TWITCH_CLIENT_ID=...
TWITCH_CLIENT_SECRET=...
TWITCH_BOT_ID=...
TWITCH_CHANNEL=...
GEMINI_API_KEY=...
```

`TWITCH_CHANNEL` – ник стримера (канал, в котором бот будет работать), **не** ник самого бота.

`TWITCH_BOT_TOKEN` и `TWITCH_BOT_REFRESH` пока оставь пустыми – они будут получены при первом запуске.

### 7. Первый запуск – OAuth-авторизация

```bash
./venv/bin/python3 bot.py
```

При первом запуске бот не сможет подключиться к чату (нет токена) и выведет в консоль OAuth-ссылку:

```
[WARNING] __main__: Токена нет. Открой в браузере и войди под аккаунтом бота:
http://localhost:4343/oauth?scopes=user:read:chat+user:write:chat+user:bot&force_verify=true
```

Открой эту ссылку в браузере. Войти нужно именно **под бот-аккаунтом**, не под стримерским. Разреши запрошенные права. После успешной авторизации twitchio перехватит callback и в консоли появятся токены:

```
Add to .env:
TWITCH_BOT_TOKEN=abc123...
TWITCH_BOT_REFRESH=def456...
```

Скопируй оба значения в `.env`. Останови бота (`Ctrl+C`).

Эта процедура делается **один раз**. В дальнейшем twitchio автоматически обновляет access token через refresh token. Обновлённые токены сохраняются в файл `.tio.tokens.json` (в .gitignore) – это внутренний механизм twitchio.

### 7а. Токен канала для наград за баллы (опционально)

Для [наград за баллы канала](#награды-за-баллы-канала) нужен второй токен – **владельца канала**: управлять наградами Twitch разрешает только ему, прав модератора у бота для этого мало. Канал должен быть компаньоном или партнёром.

Пока токена нет, бот при запуске пишет в лог ссылку:

```
[WARNING] __main__: Награды за баллы канала выключены: нет токена канала. Открой в браузере и войди под аккаунтом канала channelname:
http://localhost:4343/oauth?scopes=channel:manage:redemptions&force_verify=true
```

Открой её и войди **под аккаунтом стримера**. Награды включатся сразу, перезапуск не нужен. В консоли появятся `TWITCH_BROADCASTER_TOKEN` и `TWITCH_BROADCASTER_REFRESH` – скопируй оба в `.env`. Если не успел, при штатной остановке twitchio сохранит токен в `.tio.tokens.json`, и следующий запуск возьмёт его оттуда. Но если бот будет убит без штатной остановки (`kill -9`, пропало питание), файл не запишется – поэтому `.env` надёжнее. Если награды не нужны вовсе – `REWARDS_ENABLED=false`, и ссылка перестанет появляться.

### 8. Запуск

```bash
./venv/bin/python3 bot.py
```

Успешный запуск выглядит так:

```
[INFO] __main__: Бот запущен | Ник: botname | Сессия: 2026-09-11
[INFO] __main__: Подписка на чат #channelname
[INFO] __main__: Подписка на фоловы
[INFO] __main__: Подписка на начало и конец эфира
[INFO] __main__: Проактивные сообщения включены (раз в 15 мин)
[INFO] __main__: Оповещения о снятии проклятий включены
```

Бот запущен и слушает чат. Для остановки – `Ctrl+C` или `SIGTERM`. При остановке корректно закрывается соединение с БД.

Уровень логирования задаётся `LOG_LEVEL` (по умолчанию `INFO` для бота и `WARNING` для CLI-команд). Чтобы писать логи ещё и в файл с ротацией, укажи `LOG_FILE=bot.log`.

**Примечание:** подписка на follow-события требует scope `moderator:read:followers`. Если при запуске появляется ошибка, переавторизуйте бота по ссылке из консоли.

## Использование в чате

### Триггеры

Команды (`!who`, `!ask` и остальные) работают просто написанные в чат – обращаться к боту для них не нужно. На свободный текст бот реагирует только в трёх случаях:

1. **Слова на `сосур*` или `secur*`** – любое слово, начинающееся с `сосур` (сосурян, сосурити, сосуряночка) или с латинского `secur` (securityexpert, security). Регулярное выражение: `(?:сосур|secur)\w*` (регистронезависимое). Бот найдёт триггер в любом месте сообщения.
2. **`@securityexpert`** – прямое упоминание бота в сообщении (регистронезависимое).
3. **Реплай на сообщение бота** – ответ на любое предыдущее сообщение бота через функцию «Reply» в Twitch-чате.

Все три триггера эквивалентны. После срабатывания триггера бот извлекает текст вопроса: убирает из сообщения упоминание `@securityexpert` и слова на `сосур*` / `secur*`, оставшийся текст отправляет как промпт. Если после очистки текст пустой – отправляет исходное сообщение целиком.

### Команды

Команда пишется в чат как есть: `!who nick`, `!ask что такое FTS5`, `!roll`. Через обращение тоже работает: `@securityexpert !stat`, `сосурян !help-bot`, реплай на бота с `!fact я из Китежа`. Аргументы голой команды берутся как написаны, поэтому `!who securityexpert` находит ник бота, а не срезает его как обращение.

| Команда | Что делает |
|---|---|
| `!help-bot` | Перечисляет команды – без описаний и без пометок о правах: что делает каждая, расписано в описании под стримом, в 450 символов сообщения это уже не влезает. Имя с суффиксом, чтобы не пересекаться с `!help` других ботов в чате |
| `!stat` | Одним сообщением: сначала свои цифры за стрим и за всё время, затем итог стрима, затем канал за всё время |
| `!stat <ник>` | То же про другого зрителя: сколько написал в этом стриме, за всё время и сколько раз обращался к боту |
| `!roll` | Бросает кубик 1–100. Кто набрал меньше всех в текущей сессии – подзалупный китежанин стрима, кто больше всех – достойнейший китежанин стрима. Каждый новый ролл перезаписывает предыдущий результат игрока. Бесплатно – 3 броска за сессию, дальше [за баллы канала](#награды-за-баллы-канала). Стример катает без лимита. Пока стрим оффлайн, игра закрыта |
| `!fact <факт>` | Сохраняет факт о пользователе навсегда. **Только для VIP, модераторов и стримера.** Дублирующие факты игнорируются |
| `!defact <текст>` | Удаляет факт по подстроке. **Только для VIP, модераторов и стримера.** Удалить можно только свои факты |
| `!ascii <ссылка>` | Рисует картинку по ссылке символами Брайля – одним сообщением в чат. **Только для подписчиков, VIP, модераторов и стримера**, с лимитом за эфир: VIP 3, подписчики и модераторы 10, стример без ограничений. Без аргумента берёт последнюю ссылку из чата. Перед показом Gemini смотрит, что на картинке, и запрещённое рисовать отказывается. Описание в чат не идёт – бот его запоминает и пишет в лог, но вслух не комментирует |
| `!ask <вопрос>` | Фактический ответ без персонажа бота. Gemini отвечает как обычная модель – без системного промпта, plain text, до 3 сообщений подряд |
| `!summary` | Краткое саммари чата текущей сессии – основные темы, ключевые моменты, активные участники. До 3 сообщений |
| `!who <ник>` | Досье на юзера – бот описывает его на основе фактов и сообщений в своём стиле |
| `!versus <ник1> <ник2>` | Баттл двух юзеров – бот сравнивает по фактам и сообщениям, выбирает победителя |
| Любой другой текст | Отправляется как вопрос в Gemini вместе с контекстом |

### Классы команд

Команды делятся на два класса, и класс же определяет, в каком счётчике лежит кулдаун:

| Класс | Команды | Чем обслуживается |
|---|---|---|
| **локальные** | `!help-bot`, `!stat`, `!roll`, `!fact`, `!defact` | SQLite и текст из `CONTENT.md` – отвечают мгновенно и ничего не стоят |
| **Gemini** | `!ascii`, `!ask`, `!summary`, `!who`, `!versus` и любое свободное обращение к боту | Запрос к Gemini API: деньги, ожидание до минуты, место в семафоре |

Счётчики независимы: пока висит пауза после `!ask`, нажать `!help-bot` можно.

### Кулдаун

Одна лесенка по статусу зрителя – на оба класса и на все команды без исключений:

| Статус | Пауза | Обращений к Gemini в час | Бесплатных роллов за стрим |
|---|---|---|---|
| Стример | нет | без лимита | без лимита |
| Модератор | нет | без лимита | 10 |
| Подписчик / фаундер | нет | без лимита | 10 |
| VIP | `COOLDOWN_VIP` (10 сек) | `QUOTA_VIP_PER_HOUR` (60) | 5 |
| Фолловер | `COOLDOWN_REGULAR` (30 сек) | `QUOTA_FOLLOWER_PER_HOUR` (30) | 3 |
| Не фолловер | – | бот не отвечает | – |

Пауза держит темп, часовая квота – объём: она считает только запросы к Gemini (`!ask`, `!summary`, `!who`, `!versus`, свободный текст), потому что они стоят денег. Локальные команды ограничивает только пауза. Счётчик лежит в таблице `bot_uses`, поэтому перезапуск бота никому квоту не обнуляет, а отказ по формату (`!who` без ника) возвращает и паузу, и место в квоте.

**Без фолова бот не отвечает.** Незафоловленный зритель получает только предложение зафоловиться (не чаще раза в `FOLLOW_HINT_MINUTES`) и может посмотреть `!help-bot` – больше ничего. Фолловер ли человек, бот спрашивает у Twitch и помнит ответ `FOLLOW_CACHE_MINUTES` минут; если Twitch не ответил, зритель считается своим. Выключается через `FOLLOW_REQUIRED=false`.

Оплаченная подписка и значок модератора снимают кулдаун полностью – для них значений в конфиге нет, это правило. Если человек одновременно VIP и подписчик, применяется более щадящий вариант (подписчик).

Кулдаун ставит диспетчер, а не обработчик, – **до** сбора контекста и вызова Gemini API, чтобы быстрый спам не успевал запустить несколько генераций подряд. Если команда отвергает кривой ввод (например, `!who` без ника), кулдаун снимается обратно.

При срабатывании бот отвечает сообщением с оставшимся временем ожидания: `texts.cooldown_local` или `texts.cooldown_gemini` – в зависимости от класса.

### Обработка `!ask`

`!ask` работает иначе: Gemini вызывается **без** системного промпта (`prompts.system`) и без контекста чата/knowledge. Вместо этого берётся отдельная инструкция `prompts.ask`: «кратко, plain text, без markdown, до 900 символов». Ответ очищается от маркдауна, разбивается на куски до 450 символов и отправляется в 1–3 сообщениях подряд с паузой 1.5 сек. Первое сообщение – reply (со значком «Чат-бот»), остальные – как продолжение.

### Обработка ошибок Gemini

Если Gemini возвращает пустой ответ (вероятная блокировка входным фильтром), бот делает повторный запрос без секций `[Язык чата]` и `[Контекст канала]`. Если повторный запрос тоже пустой – бот отвечает «не удалось получить ответ». Это связано с цензурой в тексте.

## Проактивные сообщения

Бот периодически пишет в чат без запроса. Контролируется через `PROACTIVE_ENABLED` и `PROACTIVE_INTERVAL_MINUTES`.

- Пауза до каждой реплики берётся случайно между `PROACTIVE_INTERVAL_MIN_MINUTES` (5) и `PROACTIVE_INTERVAL_MAX_MINUTES` (30): ровный интервал читается как расписание
- Если чат пустой (нет сообщений в текущей сессии) – пропускает
- С вероятностью `PROACTIVE_TARGET_PROBABILITY` обращается к случайному активному пользователю из последних `PROACTIVE_ACTIVE_WINDOW` сообщений, иначе – общий комментарий
- Использует полный контекст: `[Последние сообщения в чате]` + `[Язык чата]`
- CAPS с вероятностью `CAPS_PROBABILITY`
- С вероятностью `EMOTE_PROBABILITY` добавляет случайный эмот в конец сообщения
- Отправляется через HTTP API (без reply-контекста)

## Эмоты

### Список эмотов

Хранится в `CONTENT.md`, ключ `lists.emotes` – один эмот на строку, `#` для комментариев. Поддерживает hot-reload без перезапуска бота.

Список ведётся не руками: `--sync-emotes` тянет эмоты канала через Twitch Helix API и дописывает недостающие, разложив по группам (фолловерские, сабские по тирам, за биты). Повторный запуск ничего не дублирует. Источник `global` добавляет ~300 глобальных эмотов Twitch – учитывай, что тогда эмоты канала будут выпадать заметно реже.

**Важно про отображение:** эмот отрендерится, только если он доступен *отправителю*. Сабские эмоты канала бот покажет картинкой, лишь когда бот-аккаунт оформит подписку нужного тира (tier 3 открывает все), фолловерские – когда бот зафоловлен. Иначе в чат уйдёт просто текст кода.

Сейчас в файле лежат глобальные эмоты Twitch и эмоты канала, подтянутые через `--sync-emotes`: фолловерские и сабские tier 1/2/3. Эмоты из BTTV/7TV/FFZ добавляются вручную – у канала их нет, поэтому автоматической подтяжки в проекте нет.

### Случайный эмот в ответах

С вероятностью `EMOTE_PROBABILITY` бот добавляет случайный эмот из `lists.emotes` в конец обычных ответов Gemini (`handle_default`, `!who`, `!versus`, проактив).

### Спам эмотами

Если `EMOTE_SPAM_ENABLED=true` – бот через случайную паузу от `EMOTE_SPAM_INTERVAL_MIN_MINUTES` до `EMOTE_SPAM_INTERVAL_MAX_MINUTES` минут самостоятельно отправляет в чат от `EMOTE_SPAM_MIN` до `EMOTE_SPAM_MAX` случайных эмотов (независимый фоновый цикл, аналогично проактивным сообщениям).

## Картинки в брайль-арт

Команда `!ascii <ссылка>` берёт картинку по ссылке и рисует её в чате символами Брайля – одним сообщением.

Почему брайль, а не обычный ASCII. Чат Twitch рисуется пропорциональным шрифтом, поэтому строки из `.:-=+*#%@` разъезжаются, а подряд идущие пробелы схлопываются – половина арта просто исчезает. Символы Брайля (U+2800–U+28FF) рендерятся одинаковой ширины, пустой символ U+2800 пробелом не считается и не схлопывается, а плотность вчетверо выше: одна ячейка несёт матрицу 2×4 точки.

Почему всё влезает в одно сообщение. Строка брайля не содержит пробелов – для браузера это одно неразрывное слово. Пробелы стоят только на стыках строк, перенос идёт строго по ним, поэтому каждая строка сама ложится на свою визуальную строку. Переводов строки в сообщении Twitch не бывает, и они не нужны. Ник отправителя ничего не сдвигает: первая строка арта целиком не влезает в остаток первой визуальной строки и уезжает на вторую.

Отсюда и размер: бюджет считается не в строках, а в символах сообщения. Строка из N символов стоит N+1 вместе с разделителем, поэтому рамка под картинку подбирается по её пропорциям – высокой выгоднее меньше колонок и больше строк. Ширина ограничена `PICTURE_MAX_COLS` (26): строка должна влезать в колонку чата целиком, иначе порвётся переносом. Внутри рамки картинка переводится в серый, обрезается по содержимому и растягивается по контрасту. Дальше – порог. Сначала пробуется обычный, общий на всю картинку: на контрастном рисунке он даёт самые чистые линии. Но одно число не справляется, когда большая область лежит чуть темнее него: зелёный Pepe целиком уходил в чернила и оставался силуэт без морды. Поэтому если доля закрашенных точек вышла больше 45% или меньше 5%, включается локальный порог – точка сравнивается не с общим числом, а со своим окружением, и внутри крупных однотонных пятен проступают контуры и черты. Дизеринг не используется вовсе: на шестидесяти точках в ширину он даёт шум, а не полутона.

Отдельно обрабатывается прозрачность. Вырезанная картинка на прозрачном фоне сама по себе формы не даёт: золотой кубок, положенный на белое, по яркости почти белый – порог его теряет, и остаётся путаница штрихов; у пингвина Tux по той же причине пропадает белый живот. Зато канал прозрачности знает форму точно, поэтому по нему обводится силуэт и добавляется к рисунку, а обрезка полей делается по нему же. Если прозрачность в файле есть, но по факту непрозрачна целиком, обводить нечего и она игнорируется.

Дальше заливка **выедается** (`PICTURE_HOLLOW`): из рисунка вычитается он же, ужатый на одну точку, и остаются только края. Сплошное чёрное пятно теряет форму – фотография енота выходила кляксой с контуром по краю, – а тонкие линии не страдают, они сами состоят из края, поэтому рисованному Pepe выедание ничего не делает. Поверх контура возвращаются самые тёмные места (темнее `PICTURE_SHADOW`, 45): с одной стороны тень залита, с другой идёт контур – это и даёт объём вместо проволочной схемы.

Ещё одна поправка – `PICTURE_ASPECT` (0.8): ячейка чата выше, чем вдвое своей ширины, поэтому точка брайля не квадратная и картинка без сжатия по вертикали выглядит вытянутой. Число подбирается под то, как чат рисует шрифт; меньше 1 – сжать сильнее.

Что получается: узнаваемы логотипы, эмоуты, силуэты, крупные лица. Фотографии и скриншоты – нет, точек слишком мало. У зрителя с сильно растянутым чатом арт может разъехаться: в одном сообщении нет способа поставить принудительный перенос.

Команда открыта со значка подписчика: фолловеру и не фолловеру она недоступна вовсе. За эфир VIP может нарисовать `PICTURE_PER_STREAM_VIP` (3) картинки, подписчик и модератор – `PICTURE_PER_STREAM_SUB` (10), стример не ограничен. Счёт ведётся в журнале `bot_uses` с момента начала эфира, поэтому перезапуск бота лимит не обнуляет; вне эфира окно – сутки. Считаются только показанные картинки: любой отказ лимита не стоит, а вот повтор из кэша стоит – зритель всё равно занял чат картинкой.

Ссылку можно не писать: без аргумента команда берёт последнюю ссылку из чата этой сессии. Обычный ход событий – один зритель кинул картинку, другой ответил `!ascii`, и адрес копировать не приходится.

Готовые арты кэшируются по ссылке – тридцать две последних, в памяти, до перезапуска. Чат по природе повторяется, и повтор не стоит ни скачивания, ни отрисовки, ни запроса к Gemini. Вердикт кэшируется вместе с артом, поэтому одобренная ссылка остаётся одобренной до конца эфира. Часовую квоту повтор всё равно тратит: она ограничивает, как часто зритель заставляет бота действовать, а не во сколько это обходится.

В Gemini уходит уменьшенная копия, 512 пикселей по длинной стороне: модели надо лишь понять, что нарисовано, и решить, можно ли это показывать – разрешение на такое решение не влияет, а на фотографии это срезает около 90% объёма.

Описание бот запоминает – оно пишется в `bot_interactions` с пометкой `[ascii]`, поэтому попадает в контекст и бот может говорить о показанном позже. Вслух в момент отправки он ничего не комментирует.

Ссылку даёт зритель, поэтому проверок больше, чем кода: только `http`/`https`, каждый адрес хоста проверяется на публичность (ссылка на внутренний адрес превратила бы бота в способ стучаться по локальной сети хозяина), переадресации обходятся вручную с той же проверкой на каждом шаге, содержимое обязано быть `image/*`, размер ограничен `PICTURE_MAX_BYTES`, распакованный – 40 мегапикселями, и он проверяется по заголовку файла до раскодирования, а не после.

Проверки имени при этом мало: httpx резолвит его второй раз, и запись с нулевым TTL отдала бы публичный адрес на проверку и локальный на скачивание. Поэтому проверяется ещё и адрес, с которым соединение установлено на самом деле.

Gemini здесь не рисует: рисование детерминированное, из пикселей. Он смотрит на картинку и либо запрещает её показывать (`PICTURE_CHECK`), либо коротко описывает. **Отказ закрытый**: если вердикта нет – таймаут, сбой сети или сам Gemini отказался говорить про эту картинку, – она не показывается. Неудачная проверка не кэшируется, поэтому повтор может пройти.

Это единственное место в проекте, где **фильтры безопасности Gemini включены**. Везде ещё они выключены намеренно, иначе не работает персонаж, но здесь задача обратная: бот не разговаривает, а проверяет. Классификатор Google становится вторым слоем помимо промпта – на картинку, которую он обсуждать не станет, ответа не придёт вовсе, а это уже отказ. В чат описание не идёт – картинка говорит сама за себя, а реплика следом забивает чат, – оно пишется в лог, по которому видно, что зрители таскают по ссылкам.

## Напоминание о командах

Раз в `HELP_ANNOUNCE_INTERVAL_MINUTES` (15) бот сам пишет в чат, что умеет: список команд, как его позвать свободным текстом и куда смотреть за описанием. Зритель, зашедший посреди эфира, иначе про команды не узнает – справку нужно сначала догадаться спросить.

Текст – ключ `help_announce` в `CONTENT.md`, правится на лету. Сообщение общее, без ника, и в `bot_interactions` не пишется: это объявление, а не ответ.

Напоминание уходит только **пока идёт эфир** и только если в чате кто-то писал: пустому чату рекламировать нечего. Выключается через `HELP_ANNOUNCE_ENABLED=false`.

## Игра «залупа стрима»

`!roll` бросает кубик `ROLL_MIN`–`ROLL_MAX`. Кто за сессию выбросил меньше всех – тот и залупа. В таблице `rolls` на игрока приходится одна строка за сессию (`UNIQUE(session_id, username)`), повторный бросок перезаписывает её через UPSERT – таблица хранит текущее состояние, а не историю бросков.

Бесплатных бросков – `ROLL_FREE_PER_SESSION` (3) за сессию, счётчик лежит в той же строке (`free_throws`). Сколько осталось, бот дописывает к каждому ответу `!roll`. Когда бесплатные кончились, ролл не меняется, а бот отвечает, что дальше – награда за баллы канала.

**Стример катает без лимита** и без приписки об остатке. Его броски всё равно идут в счётчик, поэтому доп. ролл за баллы у него работает так же, как у всех.

Титул нигде не лежит: он **вычисляется** при каждом обращении запросом «минимум сессии», где ничья разруливается по времени броска, а совсем полная ничья – по `id`, чтобы ответ не плавал от запроса к запросу.

Рядом с залупой – **китежанин стрима**: самый высокий ролл сессии, считается тем же способом, только наоборот. Бот дописывает «Достойнейший китежанин стрима: @nick (97 из 100).» к ответам `!roll` и к итогам наград, которые меняют ролл. Если китежанин и залупа – один человек (катал один игрок или у всех одно число), китежанин не показывается.

### Награды за баллы канала

Сверх бесплатных бросков и для саботажа – четыре награды в меню баллов канала. Бот создаёт их в Twitch сам, сам применяет и сам подтверждает: ни стримеру, ни зрителю нажимать ничего не нужно. Нужен [токен канала](#7а-токен-канала-для-наград-за-баллы-опционально).

| Награда | Цена по умолч. | Ввод | Что делает |
|---|---|---|---|
| ДОПОЛНИТЕЛЬНЫЙ ROLL | 100 | – | Бросок за себя. Бесплатные броски не тратит |
| ПЕРЕБРОС ЧУЖОГО ROLL | 250 | ник | Бот бросает за жертву, новое число заменяет её ролл. Можно и за того, кто ещё не катал, – бросок введёт его в игру. После переброса жертва 3 минуты неуязвима для новых перебросов |
| ПРОКЛЯТИЕ НА ROLL | 1000 | ник | **Пробивает щит.** Бросок жертвы не выше 75, каждый её следующий бросок опускает потолок на 5, до 25. На 25 потолок держится 15 минут, потом проклятие спадает |
| ЩИТ ОТ ЧУЖОГО ROLL | 500 | – | Переброс на тебя не действует до конца сессии. От проклятия не спасает |

Итог бот пишет в чат:

```
@carol проклял @bob и ему выпало 36 из 75, дальше потолок 70 и падает на 5 с каждым новым броском. Подзалупный китежанин стрима: @bob (36 из 100).
@bob выбил 11 из 70 под проклятием – подзалупный китежанин стрима! (бесплатных осталось 1) (следующий потолок 65)
```

Проклятие держится в строке жертвы (`curse_ceiling`, `curse_floor_at`, `curse_until` в `rolls`) и снимается само: как только потолок пробыл на дне 15 минут – тогда бот пишет в чат, что проклятие спало, – или когда началась новая сессия. Любой бросок по проклятому опускает потолок на шаг – и его собственный `!roll` или доп. ролл, и чужой переброс. Все четыре числа настраиваются в `.env` (`REWARD_CURSE_*`).

От 75 до 25 – десять бросков, а бесплатных всего три. Поэтому без докупленных роллов и перебросов проклятие обычно держится до конца сессии. Перебросы от других зрителей одновременно и бьют по жертве, и быстрее доводят потолок до дна, после которого через 15 минут проклятие спадает.

**Баллы возвращаются автоматически**, если награда не может сработать: в поле не ник, цель – ты сам, ник ни разу не писал в чате (для переброса), цель сегодня не катала (для проклятия), у цели щит, щит китежанина прошлого стрима или защита после недавнего переброса (для переброса), цель уже проклята, щит у тебя уже стоит, доп. ролл куплен при оставшихся бесплатных, стрим успел уйти в оффлайн или случилась ошибка. Причину бот пишет в чат.

Жертва саботажа не теряет свои бесплатные броски и может ими ответить – переброс и проклятие счётчик `free_throws` не трогают.

Как устроено:

- **Награды создаёт бот, а не стример в панели.** Twitch разрешает подтвердить выкуп или вернуть баллы только приложению, создавшему награду. При запуске бот сверяет награды с `CONTENT.md` (названия и описания) и `.env` (цены и лимиты) и правит только то, что разошлось. Изменения доходят до Twitch при перезапуске, а не на лету
- **Пока бот выключен, награды стоят на паузе** – иначе баллы спишутся, а применить награду будет некому. Если бот упал, не успев поставить паузу, при следующем запуске выкупы без ответа возвращаются. Так же на паузе они, пока стрим оффлайн: игра живёт в рамках эфира
- **Повтор события не бросает кубик дважды:** каждый выкуп записан в журнал `roll_actions` с уникальным id
- Лимит на зрителя за эфир для переброса и проклятия (`REWARD_ATTACK_MAX_PER_USER`) считает сам Twitch
- **Игра живёт в рамках эфира.** Сессия – стрим, а не календарный день: стрим через полночь – одна игра, перезапуск бота посреди стрима ничего не сбрасывает. Пока стрим оффлайн, `!roll` отвечает «стрим оффлайн», а награды на паузе

### Итоги прошлого стрима

В начале нового эфира бот подводит итоги прошлого и объявляет в чате:

- **Достойнейший китежанин** получает **щит от перебросов** на `ROLL_PERK_MINUTES` (30) минут
- **Подзалупный китежанин** получает **проклятие** на те же 30 минут: обычное (потолок 75, минус 5 за каждый бросок по нему), но через 30 минут спадает в любом случае. Проклятие одно – легло на первый бросок и больше не выдаётся

Отсчёт идёт не от начала стрима, а **с первого появления человека в чате** – или с первого броска по нему. Опоздавший ничего не теряет, но и не пересиживает наказание, отсутствуя: не пришёл за 30 минут после появления – бонус сгорел. Если прошлый стрим катал один человек, он получает только проклятие. Если на прошлом стриме не катал никто, бонусов нет – более ранние стримы не в счёт. Выключается через `ROLL_PERKS_ENABLED=false`.

## Память и контекст

### Сессии

Сессия – это **эфир**. Пока идёт стрим, всё – чат, `!stat`, `!summary`, контекст Gemini, игра – считается в рамках этого эфира. Имя сессии – дата и время начала стрима (`2026-09-16 19:00`). Когда стрим оффлайн, сессия – текущая дата (`2026-09-16`), как раньше: чат пишется и вне эфира.

Бот узнаёт о начале и конце эфира через EventSub (`stream.online` / `stream.offline`), а при запуске сам спрашивает Twitch, идёт ли стрим. Раз в 2 минуты он ещё сверяется с Twitch: так ловятся потерянные события и то, что случилось, пока бот был выключен. Переключается он, только если расхождение держится три проверки подряд – список эфиров в Twitch отстаёт от событий на минуту-другую. id эфира записан в таблицу `streams`, поэтому перезапуск бота посреди стрима продолжает ту же сессию. Если стрим оборвался и снова пошёл в течение `STREAM_RESUME_MINUTES` (15) минут, это тот же эфир.

Если бота выключили раньше, чем закончился стрим, время конца эфира бот при следующем запуске берёт из записи эфира в Twitch (VOD: начало плюс длительность), а если записи нет – по последнему сообщению чата, которое успел записать. Поэтому без VOD и после долгого простоя бота стрим, перезапущенный вскоре после настоящего конца, может посчитаться новым эфиром.

### Контекст при каждом ответе

При каждом обращении бот одним `asyncio.gather` собирает контекст из 4 источников (подключение к SQLite одно, поэтому запросы идут по очереди – `gather` тут про порядок кода, а не про параллельность):

| # | Секция | Откуда | Лимит | Когда добавляется |
|---|---|---|---|---|
| 1 | `[Сохранённые факты]` | таблица `facts` (`!fact`) | все свои + релевантные чужие | всегда |
| 2 | `[Последние сообщения в чате]` | `chat_messages` текущей сессии | 50 (env) | если есть сообщения |
| 3 | `[Контекст канала]` | FTS5 по `knowledge` + `chat_messages` | 10 (env) | если FTS нашёл совпадения |
| 4 | `[Язык чата]` | случайная выборка из `knowledge` | 10 (env) | всегда (если knowledge не пуста) |

### System prompt

Хранится в `CONTENT.md`, ключ `prompts.system`. Содержимое кэшируется и перечитывается при изменении файла – редактировать можно без перезапуска бота. Задаёт характер, стиль, запреты и правила использования контекстных секций.

Промпты отдельных режимов лежат там же, в секции `## prompts`: `who`, `versus`, `summary`, `summary_request`, `ask`, `proactive_user`, `proactive_general`, `user_question`, `interaction_line`. Они тоже перечитываются на лету.


### CONTENT.md

Всё, что бот произносит, лежит в одном Markdown-файле в корне проекта. Структура: `## секция` → `### ключ` → значение до следующего заголовка. Правило простое: **`.env` – секреты, числа и флаги, `CONTENT.md` – тексты.**

| Секция | Что внутри |
|---|---|
| `## prompts` | Инструкции для Gemini: `system` (личность), `ask`, `summary`, `summary_request`, `who`, `versus`, `proactive_user`, `proactive_general`, `user_question`, `interaction_line` |
| `## labels` | Заголовки секций контекста, которые видит модель: `facts`, `chat`, `channel`, `language`, `user_facts`, `user_messages`, `user_interactions`. На них ссылается `prompts.system` – меняешь здесь, поменяй и там |
| `## texts` | Все ответы в чат: `!help-bot`, `!stat`, тексты `!roll`, названия, описания и итоги наград за баллы, кулдаун (`cooldown_local` / `cooldown_gemini`), отказ по роли, подсказки по формату, сообщения об ошибках |
| `## lists` | `emotes`, `follow`, `banned` – по записи на строку, `#` в начале строки – комментарий |

Особенности:

- **Hot-reload.** Файл перечитывается при изменении mtime – перезапуск не нужен ни для личности, ни для ответов в чат
- **Опечатка не роняет бота.** Сломать разметку Markdown нельзя, поэтому проверяется смысл: дубль ключа `###` пишется в лог (побеждает последний), а файл, в котором не нашлось ни одной секции, не заменяет прошлую валидную версию
- **Плейсхолдеры** (`{user}`, `{target}`, `{seconds}` и т.д.) подставляются через `safe_format()`: неизвестный плейсхолдер логируется, а не роняет обработчик
- **Отсутствующие ключи** ловятся при запуске: `validate_content()` сверяет файл со списком `REQUIRED` в `src/core/content.py` и падает с перечнем недостающих. Незнакомый заголовок – предупреждение в лог: так всплывает опечатка в `###`
- Экранировать ничего не нужно: значение – это просто текст до следующего заголовка. Строки `<!-- … -->` и проза между `##` и первым `###` – примечания, в текст бота не попадают

## База данных

SQLite-файл `chat_history.db` в WAL-режиме. Используется одно разделяемое подключение на весь процесс (синглтон через `get_db()`).

При копировании БД копируй все три файла: `chat_history.db`, `chat_history.db-wal`, `chat_history.db-shm`.

### Таблицы

| Таблица | Тип | Описание |
|---|---|---|
| `chat_messages` | обычная | Все сообщения чата (кроме бота). Поля: `session_id`, `username`, `message`, `created_at`, `addressed` (было ли обращение к боту – по нему считает `!stat`) |
| `bot_interactions` | обычная | Пары вопрос-ответ. Поля: `session_id`, `username`, `user_message`, `bot_response`, `created_at` |
| `facts` | обычная | Факты через `!fact` / `!defact`. Unique constraint на `username+fact` |
| `knowledge` | обычная | Импортированный лор, мемы, история. Unique index на `content` |
| `bot_uses` | обычная | Обращения к Gemini: `username`, `kind`, `created_at`. По ней считается часовая квота |
| `rolls` | обычная | Результаты `!roll` по сессиям. Unique constraint на `session_id+username` – каждый ролл перезаписывает предыдущий. `free_throws` – сколько бесплатных бросков потрачено, `curse_ceiling`, `curse_floor_at` и `curse_until` – проклятие |
| `rewards` | обычная | Какие награды за баллы бот создал в Twitch: действие → id награды |
| `roll_actions` | обычная | Журнал выкупов: кто, кого, чем, было → стало, итог. Защищает от повторов и хранит щиты |
| `streams` | обычная | Эфиры канала: id эфира в Twitch → сессия бота, начало и конец. По ним перезапуск посреди стрима продолжает ту же сессию |
| `roll_perks` | обычная | Бонусы по итогам прошлого стрима: щит китежанину, проклятие залупе, когда пошёл отсчёт |
| `chat_fts` | FTS5 | Зеркало `chat_messages`, синхронизируется триггерами |
| `knowledge_fts` | FTS5 | Зеркало `knowledge`, синхронизируется триггерами |

```bash
./venv/bin/python3 bot.py                                      # запуск бота

./venv/bin/python3 bot.py --sync-emotes --dry-run              # показать, что добавится
./venv/bin/python3 bot.py --sync-emotes --replace-emotes       # пересобрать список с нуля
```

```
├── bot.py                 # Точка входа: класс Bot (twitchio), жизненный цикл, run_bot()
├── CONTENT.md             # Всё, что произносит бот: промпты, ответы в чат, эмоты, фоловы, стоп-лист (hot-reload)
├── src/
│   ├── core/                # Каркас, на котором стоят все фичи
│   │   ├── component.py     # ChatComponent: диспетчер event_message, регистрация команд всех фич
│   │   ├── commands.py      # CommandRegistry, CommandContext, CommandEntry – описание команд
│   │   ├── config.py        # Только .env: секреты, числа, флаги – с валидацией диапазонов
│   │   ├── content.py       # Загрузка CONTENT.md: Content.prompt/label/text/items, mtime-кеш
│   │   ├── database.py      # SQLite: схема и миграции всех таблиц, FTS5, запросы чата, фактов и лора, бэкап
│   │   ├── stream.py        # Сессия = эфир: StreamTracker, перезапуск и обрыв стрима
│   │   ├── logging_setup.py # setup_logging(): консоль + опциональный файл с ротацией
│   │   └── utils.py         # Чистые утилиты: CAPS, markdown, чанки, safe_format, стоп-лист
│   ├── gemini/              # Всё, что стоит запроса к Gemini
│   │   ├── client.py        # Gemini-клиент, generate() с ретраями, make_gen_config(), SAFETY_OFF
│   │   ├── context.py       # ContextBuilder: сборка секционированных промптов
│   │   ├── responder.py     # Конвейер ответа: очистка, стоп-лист, CAPS, эмот, отправка
│   │   ├── commands.py      # Болталка, !ask, !summary, !who, !versus
│   │   ├── proactive.py     # Реплики бота от себя раз в интервал
│   │   └── picture/         # !ascii: картинка по ссылке – в брайль-арт
│   │       ├── fetch.py       # Скачивание по ссылке из чата: схема, адрес, mime, размер
│   │       ├── render.py      # Пиксели в символы Брайля, ровно на одно сообщение
│   │       └── command.py     # !ascii: скачать, нарисовать, показать, подписать
│   ├── local/               # Возможности бота без Gemini
│   │   ├── commands.py      # !help-bot, !stat, !fact, !defact
│   │   ├── follow.py        # Ответ на новый фолов
│   │   ├── emote_spam.py    # Спам эмотами раз в интервал
│   │   ├── help_announce.py # Напоминание о командах раз в интервал
│   │   └── roll/            # Игра «залупа стрима»
│   │       ├── game.py        # Механика: лимит бесплатных бросков, переброс, проклятие, щит, бонусы
│   │       ├── storage.py     # Запросы к rolls, rewards, roll_actions, roll_perks
│   │       ├── command.py     # !roll
│   │       ├── texts.py       # Общие куски сообщений: китежанин, проклятие, названия наград
│   │       ├── redemption.py  # Выкуп награды: применить, сказать в чат, подтвердить или вернуть баллы
│   │       ├── rewards.py     # Награды в Twitch: создание, подписка, статусы, пауза

│       ├── main.py          # --upload-lore, --clear-lore, --list-facts, --backup, --vacuum, --sync-emotes
```

Куда класть новое: команда с генерацией – в `gemini/`, небольшая команда без Gemini – в `local/`, фича со своими таблицами, текстами и фоновыми задачами – в подпапку внутри своего пакета, как `local/roll/`. `core/` от фич не зависит, кроме диспетчера, который регистрирует их команды.
