# Twitch AI Bot

Чат-бот для Twitch-канала на **Gemini 2.5 Flash**: отвечает, когда к нему обращаются, помнит зрителей между стримами и ведёт в чате свою игру.

- **Отвечает** на обращения свободным текстом – с контекстом всего стрима, прошлого стрима и своей памяти о людях
- **Команды**: пересказ стрима, «кто такой» и батл двух зрителей, фактические ответы, брайль-арт по ссылке, статистика
- **Игра** «залупа стрима» на `!roll` и награды за баллы канала, которые бот создаёт и применяет сам
- **Сам в чате**: реплики, эмоты, напоминание о командах, приветствие фолловеров – только в живой разговор
- **Хранит** всю историю чата в SQLite с полнотекстовым поиском; все тексты бота – в одном [CONTENT.md](docs/CONTENT.md), правятся без перезапуска

Быстрый старт, подробно – в [Установке](#установка):

```bash
cp .env.example .env     # вписать пять обязательных переменных
make venv                # venv на хосте: для входа в Twitch и обслуживающих команд
docker compose up -d     # собрать и поднять бота
make oauth               # один раз: войти под бот-аккаунтом
```

Документация: [docs/BOT.md](docs/BOT.md) – как устроена каждая механика, [docs/CONTENT.md](docs/CONTENT.md) – все тексты и промпты, [CLAUDE.md](CLAUDE.md) – правила для кода. Лицензия – [MIT](LICENSE).

Стек:
- Python 3.11
- [twitchio](https://github.com/TwitchIO/TwitchIO) 3.x – подключение к Twitch через EventSub (WebSocket), не IRC
- [google-genai](https://pypi.org/project/google-genai/) – Gemini API (модель `gemini-2.5-flash`)
- [aiosqlite](https://github.com/omnilib/aiosqlite) – асинхронная работа с SQLite в WAL-режиме
- [httpx](https://www.python-httpx.org/) и [Pillow](https://python-pillow.org/) – скачивание и отрисовка картинок для `!ascii`
- [python-dotenv](https://pypi.org/project/python-dotenv/) – загрузка переменных окружения из `.env`

## Установка

### 1. Создать бот-аккаунт на Twitch

Зарегистрируй отдельный Twitch-аккаунт, который будет выступать ботом (например `mybot`). Это обычный аккаунт – специальной регистрации «как бот» не требуется. После создания аккаунта зайди в чат стримерского канала (под стримерским аккаунтом) и дай боту права модератора:

```
/mod botname
```

Модератор нужен чтобы бот мог писать в чат без ограничений Twitch по rate-limit. Делается один раз – разрешение хранится на стороне Twitch и сохраняется при переносе бота. Право `channel:bot` от канала боту не нужно: хватает модераторских прав.

### 2. Создать приложение на dev.twitch.tv

1. Зайди на [dev.twitch.tv/console/apps](https://dev.twitch.tv/console/apps) под **бот-аккаунтом**
2. **Register Your Application**:
   - **Name** – любое название
   - **OAuth Redirect URLs** – `http://localhost:4343/oauth` (twitchio поднимает локальный сервер на этом порту для OAuth-flow)
   - **Category** – Chat Bot
3. После создания зайди в **Manage** → скопируй **Client ID**
4. Нажми **New Secret** → скопируй **Client Secret** (показывается один раз)

### 3. Узнать числовой ID бот-аккаунта

Twitch API работает с числовыми user ID, а не с никами. Узнать ID бот-аккаунта можно здесь: [streamweasels.com/tools/convert-twitch-username-to-user-id](https://www.streamweasels.com/tools/convert-twitch-username-to-user-id/) – введи ник бота, скопируй числовой ID.

### 4. Получить Gemini API Key

Зайди на [aistudio.google.com](https://aistudio.google.com/) → **Get API key** → создай ключ. Бесплатного тарифа достаточно для минимальной работы бота в чате.

### 5. Установить зависимости

```bash
git clone https://github.com/exitfound/twitch-assistant-ai-bot
cd twitch-assistant-ai-bot
python3.11 -m venv venv
./venv/bin/pip install --require-hashes -r requirements.txt
```

Нужен именно Python 3.11 – на нём работает образ. Для разработки вместо этого `make venv`: тот же venv плюс pytest, ruff и pip-audit из `requirements-dev.txt`.

### 6. Настроить .env

```bash
cp .env.example .env
```

Заполни обязательные переменные (подробности в секции [Переменные окружения](#переменные-окружения)):

```env
TWITCH_CLIENT_ID=...
TWITCH_CLIENT_SECRET=...
TWITCH_BOT_ID=...
TWITCH_CHANNEL=...
GEMINI_API_KEY=...
```

`TWITCH_CHANNEL` – ник стримера (канал, в котором бот будет работать), **не** ник самого бота.

`TWITCH_BOT_TOKEN` и `TWITCH_BOT_REFRESH` пока оставь пустыми – они будут получены при первом запуске.

### 7. Первый запуск – OAuth-авторизация

Авторизация идёт **на хосте, не в контейнере**: OAuth-адаптер twitchio слушает `localhost` внутри контейнера, и снаружи до него не достучаться, поэтому порт 4343 в compose не публикуется. Бот запускается из venv в каталоге `data/` – там же контейнер держит `.tio.tokens.json`:

```bash
make oauth        # остановит контейнер, запустит бота на хосте, после Ctrl+C поднимет контейнер обратно
```

Без `make` – то же руками: `docker compose stop bot`, затем `cd data && BOT_DB_PATH=chat_history.db ../venv/bin/python3 ../bot.py`, после входа `Ctrl+C` и `docker compose start bot`. Контейнер на время входа останавливается обязательно: refresh-токен одноразовый, и два процесса на одной паре токенов разлогинят друг друга.

Без токена бот не подключится к чату и выведет ссылку:

```
[WARNING] __main__: Похоже, нет токена бота или у него не те права. Открой в браузере и войди под аккаунтом бота:
http://localhost:4343/oauth?scopes=user:read:chat+user:write:chat+user:bot&force_verify=true
(в контейнере ссылка не откроется – запусти make oauth на хосте)
```

Открой эту ссылку в браузере. Войти нужно именно **под бот-аккаунтом**, не под стримерским. Разреши запрошенные права. После успешной авторизации twitchio перехватит callback, запишет токен в `.tio.tokens.json` (права 600) и напишет в лог последние четыре символа и имя переменной для `.env`, например `TWITCH_BOT_TOKEN`: сам токен в лог не попадает. Перенеси значения из файла в `.env` и останови бота (`Ctrl+C`).

Эта процедура делается **один раз**. В дальнейшем twitchio автоматически обновляет access token через refresh token. Обновлённые токены сохраняются в файл `.tio.tokens.json` (в .gitignore) – это внутренний механизм twitchio.

### 7а. Токен канала для наград за баллы (опционально)

Для [наград за баллы канала](#игра-залупа-стрима) нужен второй токен – **владельца канала**: управлять наградами Twitch разрешает только ему, прав модератора у бота для этого мало. Канал должен быть компаньоном или партнёром.

Пока токена нет, бот при запуске пишет в лог ссылку:

```
[WARNING] __main__: Награды за баллы канала выключены: нет токена канала. Открой в браузере и войди под аккаунтом канала channelname:
http://localhost:4343/oauth?scopes=channel:manage:redemptions&force_verify=true
```

Ссылка открывается так же, как для бота, – с хоста, через `make oauth`. Открой её и войди **под аккаунтом стримера**. Награды включатся сразу, перезапуск не нужен. Токен ляжет в `.tio.tokens.json`, а в логе будут имена переменных `TWITCH_BROADCASTER_TOKEN` и `TWITCH_BROADCASTER_REFRESH` – перенеси значения из файла в `.env`. Если не успел, при штатной остановке twitchio сохранит токен в `.tio.tokens.json`, и следующий запуск возьмёт его оттуда. Но если бот будет убит без штатной остановки (`kill -9`, пропало питание), файл не запишется – поэтому `.env` надёжнее. Если награды не нужны вовсе – `REWARDS_ENABLED=false`, и ссылка перестанет появляться.

### 8. Запуск

Боевой способ – Docker Compose:

```bash
docker compose up -d          # собрать при необходимости и поднять
docker compose logs -f        # смотреть логи
docker compose restart bot    # перезапустить
docker compose down           # остановить
```

`restart: unless-stopped` поднимает бота после падения и после перезагрузки машины. Обслуживающие команды выполняются в том же образе:

```bash
docker compose run --rm bot /app/bot.py --backup /data/copy.db
```

Запуск без контейнера годится для отладки – контейнер на это время остановлен, иначе два процесса на одной паре токенов разлогинят друг друга:

```bash
docker compose stop bot
cd data && BOT_DB_PATH=chat_history.db ../venv/bin/python3 ../bot.py
```

Без `BOT_DB_PATH` бот открыл бы новую пустую базу в корне репозитория, а токены лежат в `data/.tio.tokens.json`, поэтому запуск – из `data/`.

Успешный запуск выглядит так:

```
[INFO] __main__: Бот запущен | Ник: botname | Сессия: ГГГГ-ММ-ДД
[INFO] __main__: Подписка на чат #channelname
[INFO] __main__: Подписка на фоловы
[INFO] __main__: Подписка на начало и конец эфира
[INFO] __main__: Проактивные сообщения включены (раз в 5–30 мин)
[INFO] __main__: Оповещения о снятии проклятий включены
```

Бот запущен и слушает чат. Для остановки – `Ctrl+C` или `SIGTERM`. При остановке корректно закрывается соединение с БД.

Уровень логирования задаётся `LOG_LEVEL` (по умолчанию `INFO` для бота и `WARNING` для CLI-команд). Чтобы писать логи ещё и в файл с ротацией, укажи `LOG_FILE=bot.log`.

**Примечание:** подписка на follow-события требует scope `moderator:read:followers`. Если при запуске появляется ошибка, переавторизуйте бота по ссылке из консоли.

## Что умеет бот

Здесь – что бот делает для зрителя и оператора. Как устроена каждая механика, с числами и причинами, – в [BOT.md](docs/BOT.md).

### Как к нему обращаться

Команды (`!who`, `!ask` и остальные) работают просто написанные в чат, обращаться к боту для них не нужно. На свободный текст бот отвечает в трёх случаях:

1. **Слово на `сосур*` или `secur*`** в любом месте сообщения: сосурян, сосурити, securityexpert
2. **`@ник_бота`** – упоминание целым ником
3. **Реплай** на сообщение бота

Из вопроса убирается упоминание, а если его нет – первое слово-оклик; остальное уходит в Gemini как есть, в исходном регистре. Подробно – BOT.md, «Обработка сообщений».

### Команды

Через обращение команды тоже работают: `@ник_бота !stat`, `сосурян !help-bot`. Аргументы голой команды берутся как написаны, поэтому `!who securityexpert` ищет этот ник, а не считает его обращением.

| Команда | Что делает |
|---|---|
| `!help-bot` | Перечисляет команды – без описаний: что делает каждая, расписано в описании под стримом. Суффикс – чтобы не пересекаться с `!help` других ботов |
| `!stat` | Одним сообщением: свои цифры за стрим и за всё время, затем итог стрима, затем канал за всё время. Команды к боту в числа не входят |
| `!stat <ник>` | То же про другого зрителя |
| `!roll` | Бросает кубик 1–100 в игре [«залупа стрима»](#игра-залупа-стрима). Бесплатно – 3 броска за стрим (VIP 5, подписчики и модераторы 10, стример без лимита), дальше за баллы канала. Вне эфира игра закрыта |
| `!rollstat` | Как стоят дела в игре: свой бросок и остаток бесплатных, проклятие или щит, текущие залупа и китежанин. Ничего не бросает |
| `!ascii <ссылка>` | Рисует картинку по ссылке символами Брайля одним сообщением. **Только подписчики, VIP, модераторы и стример**, за эфир: VIP 3, подписчики и модераторы 10. Перед показом Gemini смотрит на картинку и запрещённое рисовать отказывается |
| `!ask <вопрос>` | Фактический ответ без персонажа бота, до двух сообщений. Понимает уточнения к своему прошлому ответу в течение 15 минут |
| `!summary` | Пересказ текущего стрима целиком: темы и пара самых зашкварных моментов с цитатами. `!summary прошлый` или `!summary` вне эфира – прошлый стрим. До двух сообщений |
| `!who <ник>` | Горсть фактов про зрителя и пара подколов – каждый раз из новой случайной выборки всей его истории, поэтому ответы не повторяются |
| `!versus <ник1> <ник2>` | Батл двух зрителей: факты про каждого, насмешки, проигравший и прожарка обоих. Про незнакомый ник бот не выдумывает, а отказывается |
| Любой другой текст с обращением | Ответ бота с контекстом стрима, прошлого стрима и памяти о людях |

`!summary`, `!who` и `!versus` ограничены за эфир: фолловер 1, VIP 3, подписчики и модераторы 10, стример без лимита.

### Классы команд, паузы и квоты

| Класс | Команды | Чем обслуживается |
|---|---|---|
| **локальные** | `!help-bot`, `!stat`, `!roll`, `!rollstat` | SQLite и `CONTENT.md` – мгновенно и бесплатно |
| **Gemini** | `!ascii`, `!ask`, `!summary`, `!who`, `!versus`, свободное обращение | запрос к Gemini: деньги и ожидание до `GEMINI_ANSWER_DEADLINE` (30 с) |

У классов независимые паузы: пока висит пауза после `!ask`, `!help-bot` работает. Одна лесенка по статусу зрителя на все команды:

| Статус | Пауза | Запросов к Gemini в час | Бесплатных роллов за стрим |
|---|---|---|---|
| Стример | нет | без лимита | без лимита |
| Модератор | нет | без лимита | 10 |
| Подписчик / фаундер | нет | без лимита | 10 |
| VIP | `COOLDOWN_VIP` (10 с) | `QUOTA_VIP_PER_HOUR` (60) | 5 |
| Фолловер | `COOLDOWN_REGULAR` (30 с) | `QUOTA_FOLLOWER_PER_HOUR` (30) | 3 |
| Не фолловер | – | бот не отвечает | – |

Поверх личных квот – общий потолок канала `QUOTA_CHANNEL_PER_HOUR` (200 запросов к Gemini в час): он ограничивает счёт, а не одного человека. Счётчики лежат в базе, перезапуск их не обнуляет, а отказ по формату (`!who` без ника) возвращает и паузу, и место в квоте.

**Без фолова бот не отвечает**: незафоловленный зритель получает только предложение зафоловиться и `!help-bot`. Если Twitch не ответил на проверку, зритель считается своим. Выключается `FOLLOW_REQUIRED=false`.

### Сам в чате

- **Проактивные реплики** (`PROACTIVE_*`) – раз в 5–30 минут бот сам комментирует чат или подкалывает кого-то из активных
- **Спам эмотами** (`EMOTE_SPAM_*`, по умолчанию выключен) – раз в 5–20 минут от 1 до 5 случайных эмотов из `lists.emotes`; тот же список даёт случайный эмот в конце ответов
- **Напоминание о командах** (`HELP_ANNOUNCE_*`) – раз в 30 минут список команд для тех, кто зашёл посреди эфира; пропускается, если `!help-bot` только что вызывали
- **Приветствие фолловера** – случайный шаблон из `lists.follow`, без Gemini

Реплики, эмоты и напоминание – только во время эфира и только в живой разговор: если с прошлой реплики никто не написал, бот молчит. Команды разговором не считаются. Приветствие фолловера уходит на каждый фолов. Подробно – BOT.md, «Проактивные сообщения», «Напоминание о командах», «Спам эмотами».

Эмоты ведутся не руками: `--sync-emotes` тянет эмоты канала из Twitch в `CONTENT.md`. Эмот рисуется картинкой, только если доступен отправителю: сабские – при подписке бот-аккаунта нужного тира (tier 3 открывает все), фолловерские – при фолове.

### Брайль-арт

`!ascii <ссылка>` рисует картинку символами Брайля: шрифт чата пропорциональный и схлопывает пробелы, поэтому обычный ASCII-арт разваливается, а брайль держит форму и влезает в одно сообщение. Хорошо узнаются логотипы, эмоуты, силуэты и крупные лица; фотографии и скриншоты – хуже. Ссылку даёт зритель, поэтому бот качает только публичные адреса, только картинки и только ограниченного размера. Gemini не рисует, а проверяет: показывается только то, что он явно разрешил, и это единственное место, где фильтры безопасности Gemini включены. Готовые арты кэшируются по ссылке до перезапуска. Подробно – BOT.md, «Шаг 7ж: Команда `!ascii`».

### Игра «залупа стрима»

`!roll` бросает кубик: кто за эфир выбросил меньше всех – подзалупный китежанин стрима, кто больше всех – достойнейший китежанин. Повторный бросок заменяет прошлый. Сессия игры – эфир, поэтому стрим через полночь – одна игра, а перезапуск бота ничего не сбрасывает.

**Награды за баллы канала** бот создаёт в Twitch сам, сам применяет и сам подтверждает – нужен [токен канала](#7а-токен-канала-для-наград-за-баллы-опционально):

| Награда | Цена по умолч. | Ввод | Что делает |
|---|---|---|---|
| ДОПОЛНИТЕЛЬНЫЙ ROLL | 100 | – | Бросок за себя сверх бесплатных |
| ПЕРЕБРОС ЧУЖОГО ROLL | 250 | ник | Бот бросает за жертву, новое число заменяет её ролл. После переброса жертва 3 минуты неуязвима |
| ПРОКЛЯТИЕ НА ROLL | 1000 | ник | **Пробивает щит.** Бросок жертвы не выше 75, каждый следующий опускает потолок на 5, до 25; на дне потолок держится 15 минут, потом проклятие спадает |
| ЩИТ ОТ ЧУЖОГО ROLL | 500 | – | Переброс на тебя не действует до конца эфира. От проклятия не спасает |

Если награда не может сработать (не ник, цель – ты сам, у цели щит, стрим ушёл в оффлайн…), баллы возвращаются автоматически, а причина пишется в чат. Пока бот выключен или стрим оффлайн, награды стоят на паузе. Названия и описания – в `CONTENT.md`, цены и лимиты – в `.env` (`REWARD_*`); до Twitch они доходят при перезапуске.

**Итоги прошлого стрима**: в начале эфира достойнейший китежанин прошлого получает щит от перебросов, подзалупный – проклятие, оба на `ROLL_PERK_MINUTES` (30) минут с первого появления в чате. Выключается `ROLL_PERKS_ENABLED=false`.

Подробно – BOT.md, «Шаг 7а: Команда `!roll`», «Награды за баллы канала».

### Память и контекст

**Сессия – это эфир**: чат, `!stat`, `!summary`, контекст и игра считаются в его рамках. Вне эфира сессия – календарный день.

При свободном обращении бот видит весь текущий и весь прошлый стрим (вместе не больше `CONTEXT_STREAM_MAX_CHARS`, 60 тыс. символов), свою память о спрашивающем и названных людях, хронику прошлого стрима, результаты полнотекстового поиска по чату и базе знаний и случайные фразы чата для манеры речи. Если входной фильтр Gemini блокирует запрос, бот спрашивает ещё раз с меньшим контекстом.

**Долговременная память** пишется после каждого разговора – чата между паузами в 3 часа: хроника того, что было, события про людей и профиль каждого активного зрителя (кто он в этом чате, как пишет, с кем дружит и срётся). Профиль переписывается целиком, поэтому не разрастается. Реплики бота в память не попадают. Историю до включения памяти один раз собирает `bot.py --build-memory`, дальше бот ведёт её сам. Подробно – BOT.md, «Контекст Gemini» и «Память бота».

### Тексты: `CONTENT.md`

Всё, что бот произносит, – промпты, личность, ответы в чат, эмоты, шаблоны фолловеров, стоп-лист – лежит в одном [CONTENT.md](docs/CONTENT.md) и перечитывается при изменении файла, без перезапуска. **`.env` – секреты, числа и флаги, `CONTENT.md` – тексты.** Опечатка не роняет бота: файл, из которого пропал обязательный ключ, не заменяет прошлую рабочую версию, а при старте недостающие ключи перечисляются в ошибке. Подробно – BOT.md, «CONTENT.md – тексты бота».

## Эксплуатация

Бот живёт в контейнере (Docker Compose). Образ несёт зависимости, а код бот берёт из рабочего дерева, смонтированного поверх: **перезапущенный бот работает на той ветке, что сейчас извлечена**. Изменяемое состояние – на томе.

| Что | Где на хосте | Где в контейнере |
|---|---|---|
| Код и `docs/CONTENT.md` | корень проекта | `/app`, только чтение |
| База, токены, heartbeat | `data/` | `/data` |

### Повседневное

```bash
make up         # собрать образ и поднять (docker compose up -d --build)
make restart    # перезапустить бота – например, после git pull
make logs       # последние 200 строк и дальше в реальном времени
make backup     # согласованная копия базы в data/chat_history.backup-<дата>.db
make oauth      # новые токены Twitch, см. ниже
```

Обслуживающие команды выполняются тем же образом, пути – контейнерные:

```bash
docker compose run --rm bot /app/bot.py --backup /data/copy.db
docker compose run --rm bot /app/bot.py --vacuum
docker compose run --rm bot /app/bot.py --lore-sources
```

Полный список – [CLI-команды](#cli-команды). Любая CLI-команда применяет к базе новые миграции, пока ещё работает старый процесс бота; миграции поэтому только добавляют.

### Копия базы

База – `data/chat_history.db` в режиме WAL: часть данных лежит в `-wal` и `-shm`, поэтому просто скопировать один файл нельзя. Согласованную копию на ходу, не останавливая бота, делают `make backup` или `--backup`. Остановленного бота можно копировать всеми тремя файлами. Автоматических бэкапов нет.

### Повторная авторизация

Если токен бота отозван или у него не те права, бот пишет в лог ссылку для входа. Токены получаются на хосте, не в контейнере: `make oauth` останавливает контейнер, запускает бота из venv в `data/` (там лежит `.tio.tokens.json`), и после входа и `Ctrl+C` поднимает контейнер обратно. Два процесса на одной паре токенов разлогинят друг друга, поэтому контейнер на время входа останавливается обязательно. Так же получается [токен канала](#7а-токен-канала-для-наград-за-баллы-опционально) для наград.

### Откат

- **Плохой код** – `git checkout <рабочий коммит>` и `make restart`: код идёт из дерева, образ пересобирать не нужно
- **Плохие зависимости** (менялся `requirements.txt`) – тот же `git checkout`, затем `make up`: образ соберётся из старого `requirements.txt`. Прошлые образы не хранятся, `latest` пересобирается на месте
- **Образ не собирается вовсе** – бот запускается из venv на хосте: `docker compose down`, затем `cd data && BOT_DB_PATH=chat_history.db ../venv/bin/python3 ../bot.py`. Путь к базе задан явно: без него бот открыл бы новую пустую базу в корне репозитория, а токены лежат в `data/.tio.tokens.json`

### Почему контейнер устроен так

- **Дерево монтируется в `/app` только на чтение.** `CONTENT.md` перечитывается по mtime без перезапуска, CLI-команды видят те же файлы, что и на хосте, но процесс бота не может переписать собственный код и `.env`. Пишет бот только в `/data`. Единственная команда, которая правит дерево, – `--sync-emotes` (пишет `CONTENT.md`), она запускается из venv на хосте.
- **Портов нет.** OAuth-адаптер twitchio слушает `localhost` внутри контейнера, опубликованный порт до него не доходил. Новые токены – через `make oauth`.
- **`working_dir: /data`** – twitchio пишет `.tio.tokens.json` по относительному имени. Без этого токены оставались бы внутри контейнера и терялись при каждом пересоздании.
- **Образ собирается в две стадии.** Зависимости ставятся в `python:3.11-slim-bookworm` – той же Debian, что у финального образа, чтобы собранный из исходников пакет не разошёлся с его glibc, – строго по `requirements.txt` с проверкой хешей, а в финальный образ едет только каталог с пакетами и код: база – `gcr.io/distroless/python3-debian12`, без пакетного менеджера и шелла. Итог 118 МБ против 209 МБ у однослойной сборки на slim. **Шелла в контейнере нет**, поэтому `docker compose exec bot sh` не сработает, а healthcheck написан на Python.
- **Пакеты лежат в `/deps`, а не внутри `/app`.** Дерево проекта монтируется в `/app` и перекрыло бы их собой. Путь подключается через `PYTHONPATH`.
- **`USER 1000:1000`** (и `user: "1000:1000"` в compose) – тот же UID и та же группа, что у владельца каталогов на хосте, иначе бот не запишет ни базу, ни токены на том, а файлы базы доставались бы группе `root`.
- **Часовой пояс** задаёт `BOT_TIMEZONE` (по умолчанию `Europe/Moscow`): по нему именуются сессии и ключи разговоров памяти, в какой бы зоне ни работал процесс, поэтому контейнер, CLI на хосте и `make oauth` называют один момент одинаково. Неизвестное имя зоны останавливает запуск, а не откатывается молча в UTC, как это делает `TZ` (ссылки `Europe/Kiev` в актуальном `tzdata` уже нет – такое имя остановит запуск). `TZ=Europe/Moscow` в compose – только для времени в логах. Зоны в distroless уже есть, ставить `tzdata` не нужно.
- **`CMD` в exec-форме** – иначе PID 1 стал бы шеллом, который не передаёт `SIGTERM`, и база закрывалась бы жёстко при каждом перезапуске. В distroless точка входа – сам Python, поэтому команда состоит из одного пути к скрипту. Проверка штатной остановки: после `docker compose restart` у `data/.tio.tokens.json` обновляется метка времени. `stop_grace_period: 30s` – чтобы `close_db()` успел отработать.
- **Логи идут только в stdout** (`docker logs`, `make logs`). Ротация задана в самом compose (`json-file`, 10 МБ × 5 файлов), а не только в `/etc/docker/daemon.json` хоста, которого нет в репозитории. Файловый приёмник (`LOG_FILE`) выключен намеренно: второй путь молча отваливается вместе с примонтированным каталогом. Плата – история живёт, пока живёт контейнер: пересоздание её обнуляет. Хранить дольше – значит отправлять логи наружу, а не писать файл рядом.
- **Healthcheck** смотрит на `data/heartbeat`, который бот трогает раз в минуту: так ловится «процесс жив, а бот оглох», которого политика перезапуска не видит. Контейнер при этом только помечается `unhealthy`, автоматического перезапуска по нездоровью нет. Потерянное соединение с чатом бот восстанавливает сам: сторож раз в минуту проверяет сокет и переподписывается (BOT.md, «Сторож чата»).

## Разработка

CI нет, всё запускается локально из venv. Повседневные команды собраны в `Makefile`:

```bash
make venv     # venv на Python 3.11 с инструментами из requirements-dev.txt
make lint     # ruff
make test     # pytest: ~330 тестов за несколько секунд, без сети, Gemini и .env
make check    # ruff + pytest – перед слиянием ветки
make fix      # автоисправления ruff
make audit    # известные уязвимости в requirements.txt и requirements-dev.txt
make lock     # пересобрать requirements*.txt после правки requirements*.in
```

Зависимости разложены по соглашению pip-tools. В `requirements.in` – прямые, то есть всё, что импортирует код, с закреплёнными версиями; `make lock` собирает из него `requirements.txt` – всё дерево с хешами. Так же `requirements-dev.in` собирается в `requirements-dev.txt`: pytest, ruff, pip-audit и pip-tools с хешами, а общие с ботом пакеты – в версиях бота (`-c requirements.txt`). Правят только `.in`, файлы `.txt` генерируются. Образ ставит только `requirements.txt`, поэтому новая версия пакета доходит до бота, только если пересобрать образ.

Тесты лежат в `tests/` и запускаются только на хосте: в образе distroless нет pytest. Каждый тест получает пустую временную базу и `CONTENT.md`, сгенерированный из `REQUIRED`; до боевой базы, `.env` и Gemini они не дотягиваются. Как устроена обвязка – BOT.md, «Тесты».

Правила ruff – в `pyproject.toml`. RUF001–003 выключены: они срабатывают на короткое тире и на каждую кириллическую букву. Сортировка импортов (`I`) и `ruff format` не используются: оба разворачивают импорты по одному имени на строку и ломают выровненную таблицу `add(...)` в диспетчере. mypy не используется: на этом коде он находит пробелы в типах aiosqlite, twitchio и google-genai, а не ошибки.

Правила для кода и документации – в [CLAUDE.md](CLAUDE.md), раздел «When changing things».

## CLI-команды

Боевой способ – в контейнере, тем же образом, что и бот:

```bash
docker compose run --rm bot /app/bot.py --backup /data/copy.db
docker compose run --rm bot /app/bot.py --vacuum
docker compose run --rm bot /app/bot.py --lore-sources
```

`--vacuum` переписывает весь файл и на это время запирает базу: запросы работающего бота ждут до 30 секунд, а дольше – теряются. На базе в десятки мегабайт это около секунды; когда она вырастет до сотен, `--vacuum` лучше запускать при остановленном боте.

`--sync-emotes` – исключение: он переписывает `CONTENT.md`, а дерево в контейнере смонтировано только на чтение, поэтому эмоты синхронизируются из venv на хосте (`./venv/bin/python3 bot.py --sync-emotes`). Работающий бот подхватит файл сам.

Одна команда за запуск. Флаг-уточнение без команды (`--dry-run`, `--source`, `--limit`…) – ошибка, а не запуск бота: без команды `bot.py` поднимает бота, и случайный флаг запустил бы второй экземпляр рядом с работающим. Флаг, который команда не читает, тоже ошибка: `--vacuum --dry-run` иначе сжал бы базу по-настоящему, а `--probe-context --dry-run` всё равно заплатил бы за Gemini.

Ниже – тот же список для запуска из venv, без контейнера. Из корня репозитория CLI работает с базой в корне; боевая база – `data/chat_history.db`, для неё задай `BOT_DB_PATH=data/chat_history.db`:

```bash
./venv/bin/python3 bot.py                                      # запуск бота
./venv/bin/python3 bot.py --upload-lore lore.txt               # импорт лора
./venv/bin/python3 bot.py --upload-lore lore.txt --dry-run     # предпросмотр импорта
./venv/bin/python3 bot.py --upload-lore lore.txt --clear-lore  # очистить + импорт
./venv/bin/python3 bot.py --clear-lore                         # только очистить knowledge (всё)
./venv/bin/python3 bot.py --upload-lore result.json --format telegram   # чат из экспорта Telegram Desktop
./venv/bin/python3 bot.py --upload-lore article.md --format text        # статья, кусками по 1–3 предложения
./venv/bin/python3 bot.py --lore-sources                       # источники базы знаний
./venv/bin/python3 bot.py --clear-lore --source article.md     # удалить один источник (с --dry-run – только посчитать)
./venv/bin/python3 bot.py --list-facts                         # показать все факты из БД
./venv/bin/python3 bot.py --build-memory                       # память по всей истории: хроники и профили
./venv/bin/python3 bot.py --build-memory --dry-run --limit 3   # показать 3 хроники и 3 профиля, ничего не писать
./venv/bin/python3 bot.py --clear-memory                       # стереть память
./venv/bin/python3 bot.py --clear-memory --dry-run             # только посчитать, что было бы стёрто
./venv/bin/python3 bot.py --probe-context --limit 8             # замер контекста: реальные обращения к боту, now (контекст без памяти и без полного стрима) против new (как отвечает бот), ~1 цент за вопрос
./venv/bin/python3 bot.py --probe-context 33839 35280 --samples 2   # конкретные сообщения (id из chat_messages), по 2 ответа на вариант
./venv/bin/python3 bot.py --backup                             # копия БД (безопасна при работающем боте)
./venv/bin/python3 bot.py --backup path/to/copy.db             # копия в указанный файл
./venv/bin/python3 bot.py --vacuum                             # уплотнить файл БД
./venv/bin/python3 bot.py --sync-emotes                        # эмоты канала из Twitch в CONTENT.md
./venv/bin/python3 bot.py --sync-emotes channel global         # + глобальные эмоты Twitch
./venv/bin/python3 bot.py --sync-emotes --dry-run              # показать, что добавится
./venv/bin/python3 bot.py --sync-emotes --replace-emotes       # пересобрать список с нуля
```
